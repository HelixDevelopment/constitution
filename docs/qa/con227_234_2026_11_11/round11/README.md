This round answers the round-10 review, a NO-GO from the independent reviewer of round 10. That review showed
that the SendEnv reader of `scripts/release/redact_cut.sh` fails open: 13 ssh and git configurations sent an
opted-in `RELEASE_ENV_KEEP` value to a real sshd.

The round-10 mechanism parsed ssh configuration, git configuration and shell words in bash. Under §11.4.276(E)
that is replaced, not given more parser cases.

## 1. What changed

- **`rc_net`** (`scripts/release/redact_cut.sh`) is the only way the release scripts start a network child (git,
  ssh, curl, gh, glab, and the badge computer, which runs git).
  - The child gets a fixed allow-list: `PATH HOME TMPDIR` and the ssh/git/forge transport names. Each value is
    checked by shape.
  - It also gets constants: `LC_ALL=C`, `GIT_TRACE_REDACT=1` and `GIT_TERMINAL_PROMPT=0`.
  - Everything else is un-exported, including `RELEASE_ENV_KEEP` extras, locale names, `USER`, `TERM`, `PWD` and
    exported functions.
  - A second census refuses the run (125) if anything outside the list is still exported.
  - ssh can only send a variable the client has, so no ssh or git configuration can send an extra.
  - `RELEASE_ENV_KEEP` now keeps names for local children only. That is the behaviour change.
- **Locale grammar.** The codeset and the modifier are closed lists. This closes N-1, the 40-hex codeset, and
  also covers a blank, `:` and `/` after a known codeset.
- **Default-deny credential filtering** (R10-4). A test gives a network child `GITEA_PAT`, `DATABASE_DSN`,
  `SLACK_WEBHOOK`, `X_PRIVATE`, `CLIENT_CERT`, `SIGNING_SALT`, `HMAC` and `OTP`, and shows that none of them
  reaches it.
- **Spawn-site inventory and gate.**
  - `spawn_sites.md` (generated by `make_spawn_sites.py`) lists 128 sites: 52 through `rc_net` (51 network
    commands plus the badge computer), 75 local and 1 re-execution.
  - `tests/release/channel_census.py netgate` is a default-deny static gate. It fails on any network command
    started outside `rc_net` and has control needles.
  - *Correction (2026-11-13, round 12):* the two sentences above overstate the gate: the round-11 gate kept only the command words that `shutil.which()` found on the checking host, and found
    command positions with a regular expression, so a quoted, escaped, redirection-prefixed or path command word, a
    trap string, `coproc`, `alias`, `command -p` and every program absent on the checking host passed it (the
    round-11 review, F1; reviewer mutant RM30b survived the whole tag suite). It was not default-deny, and its result
    depended on the host. Round 12 replaces it with a parser that classifies every command by its syntax alone
    (`../round12/README.md`).
- **The SendEnv reader is removed** (§11.4.124). `threat_model.md` §4 records how it was wired, why no parser can
  be complete, and a further failure measured this round: the word `sendenv` in a remote URL path refused every
  keep-name.
- **R10-3.** The false claims are corrected in a dated note in `round10/threat_model.md`.
- **N-3.** The tag suite sets its own git identity.
- **N-4.** The evidence-class wording is corrected.
- **Recorder race, found this round.** Details are in section 4.

## 4. The recorder race (found and fixed this round)

The first attempt at the second suite run failed L2 (derive) and C48 (tag), in both cases "a network child holds
`TAG`, `STUB_LOG`, `PWD`, `LOGNAME`".

- **Root cause.** The cause was the test instrument, not the release code. Each child recorder appended its
  block to a shared log in several writes. Two children running at the same time interleaved their lines; one log
  line read `P == git`.
- **RED.** On the `3fe216bd` recorder, 200 concurrent git+sed pairs gave 194 misattributed records.
- **GREEN.** 0 misattributed (`race/env_census_red_green.txt`). The channel recorder went from 91 to 0
  (`race/channel_recorder_red_green.txt`).
- **Fix.** The whole block is written to a private file and appended in one step under `flock(1)`.
  *Correction (2026-11-13, round 12, F3 of the round-11 review):* the file is per process (`LOG.rec.PID`), not
  private: it is created with the caller's umask. The logs hold fake canaries only.
- **Guards.** Standing checks in both suites, plus mutants EC1 and EC2.
- **Consequence for earlier rounds.** The race could also hide a network-child finding (see `threat_model.md`
  §5). The runtime-census PASS lines of rounds 7 to 10 are therefore UNCONFIRMED as evidence.

A related observation is not fixed. One targeted harness run reported the tag suite's control at 306/1. That
failure did not recur: 2 direct runs and 4 harness-style runs all gave 307/0 (`race/ctrl_tag_loop.txt`). Its cause
is UNCONFIRMED, because the harness printed only the result line. The harness now prints the failing check names
for a control failure.
