## 3. Findings

### Minor (follow-ups, each needs a tracked item)

- **m-1. Five `tag_and_release.sh` guarantees have no test that fails when they are removed** (T2–T6): clean tree, HEAD == SHA, the remote tag equal to the local tag object when a local tag exists, the resume skip requiring the tag (not only main), and the whole gitea leg (no case runs it). Add cases from `rev_rel734c/h2.sh` (a–f) to `tests/release/test_tag_and_release.sh`.
- **m-2. `derive_release_facts.sh` can exit 0 with a partial set of facts.** It has no `pipefail` and does not check sqlite exit codes. Measured: a tracker without `reproduction_state` prints `Error: in prepare, no such column` twice, leaves `open_items_with_any_state=` empty and omits every `open_states` line, and still exits 0. Its own header says "exit 3 data missing — never a partial set of facts". The renderer refuses the missing keys downstream, so a wrong entry cannot be rendered from this. Fix: check each query's status and exit 3.
- **m-3. Waiver wording "cut on a recorded operator override"** asserts "recorded", while the same paragraph allows the decision to be only "relayed, not verbatim". Say "recorded" only when a tracked record is cited, otherwise "a relayed operator decision" (§11.4.6).
- **m-4. FINAL precondition 2 allows "a §11.4.271 waiver" instead of the §11.4.185 confirmation.** A production-class (FINAL) release needs every scope `production-ready` (§11.4.230(F.3)(2)), and that needs a valid `qa-confirmation` record (§11.4.230(E.3)(a), Q). Remove the waiver alternative for FINAL, or state that a waived FINAL would be another provisional-class release.
- **m-5. Template status and severity lines name fixed keys.** The template names Queued, RfT, In progress and Operator-blocked, and high, medium and low. A status or severity value that is new at cut time (`In testing`, `Reopened`, `critical`, `none`) would be dropped without notice, because the renderer refuses missing keys but not extra fact keys. On `fc57ad0c` the sums match (169+14+1+5 = 189, 3+53+133 = 189). Make the renderer refuse a `open_status[...]`/`open_severity[...]` key the template does not use, or render those lines from the facts as `states_block` is.
- **m-6. The shipped-template smoke case in `test_render_release_entry.sh` is skipped silently** unless `RRE_FACTS` is set (15 checks instead of 16, no SKIP line printed; §11.4.3). Print a SKIP with a reason, or ship a small facts fixture.
- **m-7. derive survivors D1/D5**: add a fixture closed exactly on the previous tag date, and decide whether that day is in or out; add an item with `UNSET` reproduction and a set investigation state.
- **m-8. §11.4.293(A): the two vehicle commits carry no `Roadmap-Item:` trailer and no tracker item covers this work.** "Registered at the cut" is a plan, not a record, and §11.4.293 / §11.4.202 want the work reported first. Since the commits are unpushed, either reword them or put the trailer on the landing merge commit, and register the item in cut step 2 (the tracker database is binary, so the reason given for registering it on `main` holds).
- **m-9. `tag_and_release.sh` maps gitea rc 3 to a GAP**, but the publisher's rc 3 also covers a bad token charset and a missing jq/curl, which are configuration failures, not an honest missing credential. Exit 5 then reads as "only gaps". Make the publisher return a distinct code for missing token, or report rc 3 as `SKIPPED-OR-REFUSED` and count it as a failure unless its stderr says `SKIPPED-NO-TOKEN`.

### Nit

- **n-1.** The CHANGELOG says "13 allowed by marker"; the vehicle gate run prints 14 `ALLOWED` lines (12 on the base). Recount.
- **n-2.** "shellcheck clean" is true at warning level; info-level notes remain (SC2015 throughout the tests, SC2086 in `sv()`). State the level.
- **n-3.** A `--release` spec is not checked against the remote's URL (`github:r1:other/repo` is accepted). The tag guards (`--verify-tag`, `--ref SHA`) limit the damage. Consider a URL/owner cross-check.
- **n-4.** On a failed fetch, up to 400 bytes of git stderr are printed. With SSH remotes this is harmless; with an HTTPS URL that has a token in it, it depends on git's URL redaction.
- **n-5.** The `run_full_suite.py` change rewords an error message so that the gate stops reading it as a call. That is a false positive of the gate's text matching; consider a gate follow-up item.
