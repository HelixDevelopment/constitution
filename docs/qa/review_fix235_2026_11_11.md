## Correctness: CON-235

- **Placement.** The check comes after the roster check and before `excluded_rows`, `read_excl_lock`, the tmp-file `open` and `os.replace`, so nothing is written before the refusal. The one caller (main, line 3200) reaches `excl_accept` only when `accept and not probs and eprobs`. For a symlinked lock, `excl_check` returns the symlink problem. For a dangling symlink, `read_excl_lock` returns None (because `isfile` is False), so `excl_check` reports the lock as "absent". In both cases `excl_accept` runs and now refuses. `Fatal(3)` propagates before the `out("accepted ...")` line.
- **Every write path to the lock.** `grep -n lock_path` shows that `excl_accept` is the only function that writes the lock (tmp + `os.replace`, lines 2104-2114). `--sync-guide` writes the guide, not the lock. The check covers every write path to the lock.
- **TOCTOU.** A symlink could be swapped in between the `islink` check and `os.replace`. `os.replace` renames onto the link and does not follow it. I measured this in a scratch dir:
  ```
  $ echo T > target; ln -s target lock; echo NEW > tmp; python3 -c "os.replace('tmp','lock')"
  -rw-rw-r-- ... lock          # link replaced by a regular file
  T                            # target untouched
  ```
  The race therefore ends in the pre-fix behaviour: the link is replaced and the change is visible in git. Nothing is written through the link. On a single-uid host this is acceptable. Finding N-1 (nit).
- **Pre-existing write-through hazard (not introduced here).** `open(lock_path + ".tmp.<pid>", "w")` follows a symlink planted at that tmp name, so a write can go through a link there. The pid is not known in advance, so this is hard to exploit, but the write is not `O_EXCL|O_NOFOLLOW`. Finding M-1 (minor follow-up, out of the CON-235 scope).
- **Parent directory.** If `config/` itself is a symlink, `islink(lock_path)` is False and the write goes through the directory link. Nothing checks that the lock is tracked or equal to HEAD; the roster has that check, the lock does not. Finding M-2 (minor follow-up, out of scope).
