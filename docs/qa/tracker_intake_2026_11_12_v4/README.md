## Decisions with evidence

- **CON-339, `created_at`.** The engine's `close` rewrites `created_at` (reproduced in
  `engine_repro.txt`, section G1). The vehicle closed CON-243, so its `created_at` moved. No engine
  command takes a `created_at` value: outside the tests the engine names the column only in the
  schema default `datetime('now')` (`db.go:392`) and in the migration copy (`db.go:417`, `:424`).
  Section 11.4.93 forbids a hand edit. Decision: not restored. The plan prints a NOTE, `verify`
  reports it as KNOWN, never as a pass, and the engine defect stays tracked as CON-339.
- **M-14, CON-308's reopen counter.** The vehicle's history rows are not carried by a landing (the
  engine writes new rows on replay; A16), so the counter raised by the intake correction does not
  reach the landed tracker. The vehicle's own history cannot be edited (section 11.4.93). `verify`
  reports the lifecycle-count difference as KNOWN.
- **N-1, sqlite sidecars.** The tools open every database with `mode=ro`. In WAL mode sqlite may
  create `-shm` / `-wal` files next to it; the database bytes do not change (suite case "plan: the
  three databases are not written"), and `docs/workable_items.db-shm` / `-wal` are gitignored
  (`.gitignore` lines 46, 47). `immutable=1` was not used: it ignores a live WAL and can read stale
  data, a false read worse than a sidecar. `replay --apply` refuses a copy with a non-empty `-wal`,
  because its sha256 check reads the main file only.
- **N-3, home paths.** The 21 lines are in round-1 captured review logs; captured evidence is never
  rewritten (the guide's rule), and no secret shape matches them. Round 4 adds captured scratch paths
  in three RED files (`red/od_reopen_red.txt`, `red/lint_r3/DM13b.out`,
  `red/probe_badcases_pre_binding.txt`) and in the run outputs under `runs/`, kept verbatim for the
  same reason; a scan for the secret shapes over the copied evidence found none (its positive control,
  a fake token of the same shape, was found).
- **LC9 was an equivalent mutant.** The PATH-MISSING regex ended in the class `[\w/]`, so a match
  could never end in punctuation and the `rstrip` was dead code: the mutant that removes it could not
  die. Round 4 widens the end class to `[\w/.]` and adds a golden-good needle with a trailing dot;
  the mutant now fails the built-in needles (`golden-good-trailing-punctuation (PATH-MISSING)`) and
  the suite.
- **The tracked database differs from a backup copy only in its header.** Measured with `cmp -l`:
  the change counter and the sqlite version of the writer (the engine against Python's backup);
  every table is identical row by row.

## How to re-run

From the repository root, with the engine binary `WI=scripts/workable-items/bin/workable-items`:

```
bash tests/workable_items/test_intake_lint.sh
INTAKE_LINT_EXTRA=--no-selfcheck bash tests/workable_items/test_intake_lint.sh
bash tests/workable_items/test_remint_ids.sh
bash tests/workable_items/test_intake_lint_mutations.sh

bash docs/qa/tracker_intake_2026_11_12_v4/make_evidence.sh "$WI" 02c10935 fix227=fed933c0 main=bd0036bd main-replay=bd0036bd:no-ff
```

The RED runs use the round-3 code from git: `git show 53b6d9ed:scripts/workable-items/intake_lint.py`
(set `INTAKE_LINT=` to it) and `git show 53b6d9ed:scripts/workable-items/remint_ids.py` (set
`REMINT_IDS=` to it). `fed933c0` and `bd0036bd` must be present in the clone.

## UNCONFIRMED and UNKNOWN

- **UNCONFIRMED: a real landing.** Every landing here ran on scratch copies. The order (fix227 first)
  is the plan, not an event; if fix227 changes again before it lands, the fix227 simulation must be
  run again against its final database (a plan is valid only for the target sha256 it records).
- **UNCONFIRMED: the exports.** The HTML, PDF and DOCX exports are not scanned (C8); that every
  exporter carries the Markdown text unchanged is not checked here.
- **RED of the re-mint suite on the round-3 tool is an interface RED.** The round-3 tool has no
  three-way `plan` and its `replay` takes other arguments, so the suite reaches 70 cases (23 pass, 47
  fail) and then stops at a fixture step with exit 2, because the round-3 landing did not produce
  the state the next fixture builds on. It shows the round-3 tool fails the round-4 contract; it is
  not a per-case RED for all 138 cases.
- **F3 and F4 RED captures were made with drafts.** The draft tool is kept as
  `red/remint_ids_pre_scriptforeign.py.txt`; the draft suite of the F4 capture is not kept, so that
  capture cannot be replayed byte for byte (its finding is pinned by mutants S1..S3 instead).
- **UNKNOWN: engine `validate` modes.** Only the default `validate` ran; the reproduction closure gate
  (`states freeze`) is not armed in these databases.
- **UNCONFIRMED: Pyright and network.** Pyright 1.1.414 ran from the user's PATH, without network
  isolation; that the npm CLI made no network call is not asserted.
- **Relayed decisions.** Operator decision 8 and the round budget decision of 2026-11-11 are relayed
  by the conductor, not verbatim; not re-checked with the operator here.
- **Host load** was about 40 to 48 on 16 cores during every run; no duration is a performance claim.
