## 1. Goal

A user can answer, review and change every decision about the Jev decision layer and other decision models (local through llmctl and Claude Toolkit aliases, hosted through Jev/TypeSafe or OpenRouter) from a terminal or from a CLI agent. Answers are stored as LOCAL PROJECT OVERRIDES that inherit from the constitution and never copy or weaken it (§11.4.35). Re-running the wizard changes decisions idempotently.

## 2. Facts the plan stands on

## 3. Files and inheritance

| File | Scope | Content |
|---|---|---|
| `<project>/.constitution/decisions.yml` | project | `schema_version: 1`, `inherits:` (the detected constitution path, `submodules/constitution` or `constitution`), `decisions:` with ONLY the overridden keys, sorted, no timestamps (byte-deterministic). |
| `<project>/.constitution/decisions.sha256` | project | sha256 of the file the wizard last wrote; a mismatch means the file was edited outside the wizard. PROVENANCE ONLY: anyone who can write the yml can rewrite the sidecar, so it detects accidental hand edits, not an attacker; every value is validated against the catalogue regardless. |
| Managed block in `CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, `QWEN.md` (only files that already exist, plus any file passed with `--doc`) | project | Between `<!-- BEGIN constitution-decisions ... -->` and `<!-- END constitution-decisions -->`. States that decisions inherit from the constitution, points at `.constitution/decisions.yml`, lists overrides. Text outside the markers is never touched. |
| `${CONSTITUTION_DECISIONS_USER_FILE:-${XDG_CONFIG_HOME:-$HOME/.config}/constitution/decisions.yml}` | user | Same schema; written ONLY with `--scope user`. The only file the wizard may write outside the project. |
| `<project>/.constitution-install-backup/<UTC>-decisions/` | project | Copy of every file the run is about to change (created only when something changes). Only the newest `CONSTITUTION_DECISIONS_BACKUP_KEEP` (default 20) backups the wizard created (name pattern `<UTC>-decisions[-n]`) are kept; nothing else in the directory is touched. The directory should be listed in the project `.gitignore` (the installer, builder W2, owns that entry); the wizard does not edit `.gitignore`. |
| `<dir of the user file>/.decisions-backup/<UTC>-decisions[-n].yml` | user | Backup of the user file before a `--scope user` write, in a 0700 directory BESIDE the user file (never in a project tree); the path is printed; bounded like the project backups. |
| `<project>/.constitution/decisions.intent` | project | Exists only while a write is in progress (sha of the new file); after a crash the next run finishes or redoes the write, and `--check` does not report the crash as a hand edit. |
| `<project>/.constitution/.decisions.lock` | project | flock target, opened with `O_NOFOLLOW` (a symlinked lock file is refused); a second concurrent writer exits 5. It stays on disk (empty). The layers are re-read after the lock is taken. A `--scope user` write locks `.decisions.lock` beside the user file (directory mode 0700). |

Precedence (lowest first): constitution defaults < user file < project file < `JEV_BOOTSTRAP_*` env < `--answers` file < `--set` flags. Env consent values (`JEV_BOOTSTRAP_CONSENT`, `_ALLOW_CLONE`, `_INSTALL_TOOLS`, `_AGENTS`, `_DOWNLOAD_PROFILE`) are taken only with `--accept-env`; without it the run prints a note naming the ignored variables. `JEV_BOOTSTRAP_MODE` maps to `layer.mode` without the flag (it can only be validated, not escalate consent). A locked key can only be set to its constitution value or a stricter one, at every level.

Contradictions: `layer.mode` other than `enforce` with any type in `enforce`; a type both `enforce` and in `exclusions.never_enforce`; `hosted.allowed=false` with `hosted` in `endpoints.preference`. A write that would CREATE a contradiction not already present is refused (exit 4). A contradiction that already exists (typically one layer changed after the other was written: user layer in project A, project layer in project B) is REPORTED and never refuses a read or recovery path: `--show` prints a WARNING (and a `contradictions` list in `--json`), `--plan` warns on stderr, `--check` prints `check: WARNING: contradiction ...` and exits 4 (not clean) without being a refusal, and `--reset`, `--unset`, `--import`, `--export` and `--scope user --reset` work, so the project recovers without a hand edit. Any string value that looks like key material (prefixes `sk-`, `ghp_`, `AKIA`, `xox`, or 32+ characters of token alphabet) is refused and never echoed. Values and keys with control characters (code below 0x20, or 0x7f) are refused. An unknown or secret-shaped KEY is never echoed: messages show `key#<sha256 prefix>`. Every regex is matched against the whole string (`fullmatch`), and the dumped YAML is re-parsed and compared before it is written. `schema_version` must be the integer 1 (not `1.0`, `true` or `"1"`).

## 5. Flows

```mermaid
flowchart TD
  A[start] --> B{action flags?}
  B -- show/check/export --> R[read layers, validate] --> O[print, exit 0 or 4]
  B -- set/unset/reset/import/answers --> M[merge into overrides]
  B -- none --> T{TTY on /dev/tty?}
  T -- no, not --non-interactive --> E2[exit 2]
  T -- yes --> Q[prompt each decision, Enter keeps] --> M
  M --> V{validate: closed keys, locked floors, contradictions, secrets}
  V -- refused --> E4[exit 4, nothing written]
  V -- ok --> D{--dry-run?}
  D -- yes --> P[print plan + bootstrap command, exit 0]
  D -- no --> L[take lock] --> C{changed?}
  C -- no --> N[no-change, exit 0]
  C -- yes --> K[backup then atomic writes: yml, sha256, managed blocks] --> OK[exit 0]
```

- First run: no file exists; the wizard asks (TTY) or takes answers; writes the file and blocks.
- Re-run or change: `--set key=value`, `--unset key`, or the interactive pass; identical input is a byte-stable no-change.
- Import and export: `--export -` (stdout) or a path inside the project but not under `.git/` or `.constitution/`; an existing file is refused unless `--force-export` (then a backup is taken first); `--import FILE` replaces the overrides after validation.
- Reset to inherit: `--reset` writes an empty override map; the block then says everything is inherited.
- Dry run: `--dry-run` with any change prints the diff and the bootstrap command and writes nothing.
- Non-interactive: `--non-interactive` (or `CONSTITUTION_DECISIONS_NON_INTERACTIVE=1`, or `JEV_BOOTSTRAP_NON_INTERACTIVE=1`) maps `JEV_BOOTSTRAP_MODE` into `layer.mode`; the consent variables (`JEV_BOOTSTRAP_AGENTS`, `_CONSENT`, `_ALLOW_CLONE`, `_INSTALL_TOOLS`, `_DOWNLOAD_PROFILE`) are mapped only with `--accept-env`.
- Docs: default targets are the existing CLAUDE.md, AGENTS.md, GEMINI.md and QWEN.md; `--doc FILE` adds a markdown file inside the project (never under `.git/` or `.constitution/`); a non-markdown file is accepted only if it already carries the markers. Line endings (LF or CRLF) are preserved; a non-UTF-8 doc is refused cleanly (exit 4).
- Bootstrap command: the printed command implies exactly the recorded consents. `--yes` is printed only when `llmctl.clone_consent` is true (bootstrap's `--yes` also grants clone consent); `claude` is in `--agent` only with `agents.settings_json_consent` (jev-setup edits settings.json); agents with consent but not wired are listed in a `not wired` note; `--allow-clone`, `--install-tools` and `--enforce` follow their decisions; `JEV_HOSTED_PROBE=0` is set when hosted is off.
- Scopes: `--scope project` (default) and `--scope user`; per-agent choices are the `agents.<agent>.*` keys.
- Plan: `--plan` shows the effective decisions, the read-only `jev-status.sh --json --no-validate` result, `llmctl plan --json` when `--probe` is given (honest SKIP when llmctl is absent) and the bootstrap command line.

## 6. Command-line interface and exit codes

`constitution_decisions.sh [--project-root DIR] [--scope project|user] [--show [--json]] [--check] [--set K=V]... [--unset K]... [--reset] [--answers FILE] [--import FILE] [--export FILE|-] [--force-export] [--dry-run] [--non-interactive] [--accept-env] [--plan [--probe]] [--doc FILE]... [--accept-external-edits] [--version] [--help]`

`--check` exits 4 when the file is invalid or tampered, when a managed doc block differs from what the current decisions would render (drift), or when the effective decisions contain a contradiction (reported as a WARNING, not a refusal).

`--inherits PATH` records and accepts an inherited constitution path other than `submodules/constitution` or `./constitution`; it is the explicit confirmation that a directory without a repository, without an inherited constitution, or the HOME directory is a project. Without it every write needs: a `.git` in the root or an ancestor, an existing `submodules/constitution` or `./constitution` (or the root being the constitution itself), and a root that is not HOME (exit 3). Read-only actions have no such precondition. A project root inside a `.git` directory is refused (exit 3).

Number grammar (values given as text, `--set`/`--answers`/TTY): integers `[+-]?[0-9]{1,15}`; floats `[+-]?(digits[.digits]|.digits)([eE][+-]?[0-9]{1,4})?`; ASCII digits only. Underscores, hex, `nan`, `inf`, thousands separators and non-ASCII digits are refused (exit 4). Native YAML numbers in files are range-checked as before.

| Exit | Meaning |
|---|---|
| 0 | done (including no-change, show, plan) |
| 1 | internal failure |
| 2 | usage error, or interactive run with no TTY and no `--non-interactive` |
| 3 | precondition: project root missing, inside `.git`, bare/HOME/no inherited constitution without `--inherits`, python3 or PyYAML absent, path resolves outside the project, symlinked target, or a write target inside a git submodule (`.gitmodules` path), another repository (a directory with its own `.git`) or the inherited constitution |
| 4 | refused: unknown key, weakening a locked rule, a NEW contradiction, secret-like value, malformed or tampered file, broken markers (also `--check` not clean) |
| 5 | another run holds the lock |

## 7. Edge cases and combinations

| Case | Behaviour |
|---|---|
| No llmctl | `--plan --probe` records `llmctl: SKIP (not found)`; decisions still work. |
| No endpoints / no key / placeholder key | not the wizard's job to probe; the plan shows the jev-status record or SKIP. |
| Offline | the wizard makes no network call at all. |
| Conflicting overrides (user vs project) | project wins; `--show` lists the conflict with both sources. |
| Same key twice in one command | refused (exit 2). |
| Override weakening a constitution rule | refused (exit 4), message names the anchor; nothing written. |
| Unknown key | refused (exit 4). |
| Tampered file (sha mismatch) | `--check` exit 4; writes refused unless `--accept-external-edits` (the edited content is still validated). |
| Duplicate or unbalanced markers in a doc | refused (exit 4); the doc is not changed. |
| Doc or decisions file is a symlink, or `--export`/`--doc` path outside the project, under `.git/` or `.constitution/` | refused (exit 3). |
| Existing `--export` target | refused (exit 3) unless `--force-export`. |
| Managed block edited by hand | `--check` exit 4 (drift); the next write renders it again. |
| Managed block present but `.constitution/decisions.yml` missing | `--check` exit 4 (stale block); the gate reports FAIL, never SKIP. |
| Code fences (CommonMark §4.5, top level) | a fence opens with up to 3 spaces then 3+ backticks or tildes; a backtick fence's info string may not contain a backtick (such a line is not a fence); it closes only with the same character, at least as long, up to 3 spaces of indentation and nothing but spaces/tabs after it; a leading tab or 4+ spaces is indented code, not a fence. Lines end only at LF, CRLF or CR (not U+2028 or form feed). A doc that ends inside an unclosed fence is REFUSED untouched when the block would have to be appended (it would land inside the code and be invisible to the next run). Every write is verified: the result must hold exactly one live block equal to the new block, else the doc is refused untouched; so a doc can never accumulate blocks. Fences inside list items or block quotes are not modelled; that is safe because the markers are column-0 lines and the post-write check refuses anything the scan does not see. |
| Markers | a marker is an EXACT whole line (`<!-- BEGIN constitution-decisions[ (...)] -->`, `<!-- END constitution-decisions -->`); markers inside fenced code blocks are ignored; an END line with trailing text and `-legacy` markers are not ours (a stray one makes the doc unbalanced and it is refused untouched). |
| Secret-shaped key, key segment, path or value | refused before anything is written (exit 4, or 3 for paths) and never echoed: every printed message, `--show`, `--json` and every rendered block pass through a redaction; an unknown or secret-shaped key is shown only as `key#<hash>`. |
| `--dry-run` | writes nothing in every mode, including `--export`, `--force-export`, backups and the lock file. |
| Locked keys | never stored: dropped on write and on read. A stored `keys.var_names` that differs from the current provider pin is ignored with a note (the pin governs). An invalid stored entry blocks unrelated writes, but `--reset`, `--import` or `--unset <key>` recover without a hand edit. |
| Contradictions | a question type in `enforce` while `layer.mode` is not `enforce`, a type both in `enforce` and in `exclusions.never_enforce`, and `hosted.allowed: false` with `hosted` in an explicit `endpoints.preference` are refused; with `hosted.allowed: false` and an inherited preference, `hosted` is dropped from the effective preference. |
| In-project symlinked doc (for example `AGENTS.md -> CLAUDE.md`) | resolved and de-duplicated (one block); a symlink that leaves the project, points into `.git/`, `.constitution/` or `.constitution-install-backup/`, or at a non-regular file is refused. |
| OS errors and unhealthy targets | before the first write every target is pre-flighted: its directory must exist and be writable on a writable file system with room for the new content (plus 1 MiB), and every existing target must be a single-link, writable regular file. A read-only (0444) doc and a hard-linked doc are refused (exit 3) instead of being silently replaced or split. A failure the pre-flight cannot see (for example permissions changed mid-run) exits 3 with the file and the OS reason, never a traceback or an absolute path; `.constitution/decisions.intent` records the unfinished change and the next successful run completes it. Just before each replace the target is re-read; if someone else changed it during the run, nothing more is written (exit 4) and the edit survives. New files honour the umask (base 0666; the user file 0600). Inputs larger than 4 Mi characters and non-regular files (FIFO, device) are refused. Live EROFS/ENOSPC could not be exercised on the test host (user-namespace mounts refused); those two branches are unit-tested with a patched `statvfs`. |
| Printed text | every message passes `redact`: secret-shaped runs become `[redacted]` (the generic 32+ token pattern now needs a digit AND a letter, so anchor text like `review/merge/finding/...` is kept) and control, C1, bidi and line-separator characters are shown as `\uXXXX`. Paths and values holding them are refused. Argparse errors show only `unrecognized arguments` or `invalid choice` with `(value not shown)`. |
| `--export` with a missing directory, onto a directory, or into `.constitution-install-backup/` | refused (exit 3), no traceback. `.constitution` as a regular file: refused (exit 3). |
| Bootstrap environment census | every `JEV_`/`LLMCTL_`/`CLAUDE_`/`TYPESAFE_`/`OPENROUTER_`/`HELIX_` variable read by `scripts/jev/bootstrap.sh`, `lib_decide.sh`, `lib_keys.sh`, `jev-calibrate.sh` and `jev-probe.sh` is classified in the engine (`BOOTSTRAP_ENV` = unset, `BOOTSTRAP_PASS_ENV` = kept: state/config/evidence locations, the key file location and the key variables, read by name only). The printed command unsets every `BOOTSTRAP_ENV` name plus any new name a run-time re-scan of those scripts finds, then pins `JEV_CALIBRATE_FLOOR` and `JEV_CALIBRATE_MIN_SAMPLE` ALWAYS (jev-calibrate.sh reads them unclamped, so an ambient 0.5 would weaken enforcement), the download profile when recorded and `JEV_HOSTED_PROBE=0` when hosted is not allowed. `JEV_BOOTSTRAP_NESTED` (skips the advisory gates) and `JEV_BOOTSTRAP_HOME` (managed-clone root; the default `<JEV_HOME or HOME>/.local/share/helix` applies) are unset. `tests/decisions/test_round4.sh` fails when one of those scripts gains a variable the engine has not classified. Honest boundary: the advisory gates bootstrap runs from `scripts/gates/`, `llmctl`, `jev-setup.sh` and `claude_toolkit` read further variables that this census does not cover. |
| Environment | every `JEV_BOOTSTRAP_*` variable that becomes a decision (`MODE` included) is recorded only with `--accept-env`; without it a note names the ignored variables. The printed bootstrap command starts with `env -u` for every variable `bootstrap.sh` reads, so ambient values cannot add consent; the download profile is pinned explicitly. |
| Killed mid-write | atomic rename leaves old or new file; the stale temp file is removed on the next run; the lock dies with the process. |
| User file inside the project | `--scope user` writes, dry-runs, the lock and the backups go beside the user file; when that directory resolves (symlinks followed) inside the project being operated on, the run is refused (exit 3) and nothing is created in the project. `CONSTITUTION_DECISIONS_USER_FILE` must be an absolute path (a relative one would resolve against the working directory). Forensic reason: on 2026-10-29/30 a builder mutant (P19, backups moved to the working directory) ran its suites with the real repository as working directory and left `.decisions-backup/` (4 x 337-byte copies of a test user file) in the repository root; the leak was removed after inspection. |
| Multi-project | every project has its own file; `--project-root` selects one; nothing is shared except the user scope file. |
| Concurrent runs | second run gets exit 5. |
| Write target in another repository or the inherited constitution (round 4, I-2) | every write target is resolved (symlinks followed) and refused with exit 3 when it lies under a `.gitmodules` path, under `submodules/constitution`, `./constitution` or the `--inherits` path, or below any directory that has its own `.git` other than the project root. This covers `--doc`, `--export` and default docs. A DEFAULT doc (CLAUDE.md, AGENTS.md, ...) that is a symlink into such a place is skipped with a note instead of failing the run (it is the inherited carrier, not the project's). A gitlink that is neither in `.gitmodules` nor checked out is not detected (UNCONFIRMED shape; no subprocess is run to read the index). |
| Backups and key material (round 4, I-4) | a backup copy of any non-Markdown file (decisions.yml, the user file, an `--export` target) that holds key-shaped runs is written REDACTED with a note on its first line (the backup is lossy for those runs by design); Markdown docs are copied faithfully. Backup directories are 0700 and files 0600. The wizard prints a note when `.constitution-install-backup/` is not in the project's `.gitignore`; it never edits `.gitignore`. **Round-7 notes (closed classes, honest residuals).** (1) Process boundary: `run_cli` maps engine errors to their codes, Ctrl-C to 130, a closed pipe to one line plus a silenced stdout (round 8: stdout and stderr are flushed INSIDE the boundary on EVERY way out - success, the engine-error, internal-error and Ctrl-C paths and argparse `SystemExit` alike (round-8 review B-2: the error paths used to skip it and still exited 120) - so a failed final flush is mapped there; it decides the exit code only for a run that otherwise succeeded, a failed run keeps its own code and message - a closed pipe is rc 1 `internal error (BrokenPipeError)`, a full device is rc 3 `blocked: No space left on device` - and stdout is then pointed at /dev/null; before, Python's own exit-time flush printed `Exception ignored while flushing sys.stdout` and exited 120, also after a successful `--set`; the exit code 3 after a successful write means the output could not be delivered, the write itself had happened), and EVERY other exception to `constitution_decisions: internal error (<Type>)` (type name only, never the message, a path or a traceback) with exit 1; `sys.excepthook` is installed to the same emitter; `SystemExit` (argparse help/version) passes through.
