## What is covered, exactly

The runner covers the test entry points that a **census** finds and the **manifest** declares. Nothing else.

- Census: every tracked or untracked-not-ignored file outside submodule paths that is
  - named `test_*.sh`, `*_test.sh`, `*selftest*.sh`, `run_all.sh`, `test_*.py`, `*_test.py` or `*_test.go`, or
  - a script (`.sh`, `.bash` or `.py`, any letter case, or no extension with a shell or python shebang) that lives under a `tests/` or `test/` directory, or whose name contains `test`, `mutant`, `mutation`, `smoke` or `selftest` (any case).
  A Go test file counts toward its nearest `go.mod` module, which runs as `go test -count=1 ./...`.
- A file name with a newline or TAB, and a dangling symlink outside a `fixtures/` directory, are census problems (exit 3). A dangling symlink inside `fixtures/` is listed and needs a fixture row.
- Positive control: if `git ls-files` lists nothing, the census is blind and the runner stops (exit 3).
- Before anything else the census function runs on a built-in fixture (the needle) with one known file per rule, decoys and a submodule path. If it does not return exactly the expected set, the runner stops with exit 3.
- Every census file needs exactly one manifest row. A file without a row, a row without a file, or a row that breaks a rule stops the runner with exit 3 and `RESULT: MANIFEST-MISMATCH`; nothing runs.
- Not covered: the contents of submodules (each owns its suites).

`bash scripts/run_full_suite.sh --verify-manifest` prints the census by kind and class. The line below is generated; `--verify-manifest` refuses when it is stale.

## Manifest classes

| Class | Meaning |
|---|---|
| `entry` | run as a unit (runner `bash`, `sh`, `python3`, `go-test`, or one of the three run_all runners) |
| `member` | run only through its `covered_by` entry, never on its own, so nothing runs twice |
| `fixture` | a file under `fixtures/` that matches a rule but is not a test; never run |
| `excluded` | a census file that is not a test (a gate, a library, a fake server, an oracle); never run; the note must be `reason: <why>` |

Rules the runner checks:

- A `member` must really be run by its `covered_by` entry. This is decided by a shell model of the entry: a lexer, a parser and an abstract interpreter that follow literal values, variables, arrays, `for` lists, functions, `$(...)`, `source`, and the `bash` / `sh` / `python3` invocations in executable code. Comments, heredoc bodies and quoted text are not code. Names are never matched against the text of the file.
- An `excluded` row whose reason is `reason: helper, sourced by <path>` must really be sourced by `<path>` in that model.
- A heavy-looking name (`mutation`, `mutant`, `mutate`, `chaos`, `stress`, `perf`, `meta_test`, `smoke`) has tier `heavy` unless the row carries an `override:` note. A member of a heavy entry is heavy.

`run_all.sh` runners:

| Runner | Default mode | Full mode |
|---|---|---|
| `runall-whole` | run once | run once |
| `runall-quick` | `run_all.sh --quick` | `run_all.sh` |
| `runall-members` | run_all not run; its default members run alone | run_all once |

`runall-quick` is accepted only when the model, run with `--quick`, shows that every heavy member is dropped. In default mode each dropped member is listed as `SKIPPED-heavy` with the reason `heavy_excluded (dropped by --quick of <run_all>)`, and `--list` prints it.

Regenerate after adding or removing tests: `bash scripts/run_full_suite.sh --generate-manifest --write` (existing rows are kept; new helper-like files get an `UNREVIEWED` excluded row that must be given a reason by hand), then `--sync-guide`, then review the diff.

## Verdicts

`PASS`, `FAIL`, `SKIP(reason)`, `TIMEOUT`, `ERROR`, plus `SKIPPED-heavy` (heavy unit, not run in default mode) and `NOT-RUN` (filtered by `--only` or interrupted).

- `TIMEOUT` only when the runner's own timer fired. A suite's own exit 124 or 137, or a death by signal, is `ERROR` with the reason.
- `SKIP`: exit 77, or a SKIP decision of the summary parser. Never counted as PASS.
- Exit 0 otherwise: the summary parser reads the last 8 non-empty lines of the log.
  - Word signals: `RESULT`, `VERDICT`, `RUN_ALL`, `STATUS`, `SUMMARY` or `OVERALL` (any case) followed by `:` or `=` and a pass, fail or skip word that is not part of a number.
  - Counts: `key=N`, `key: N`, `N word`, `word N` and `N of M` forms; each number is bound to one word with a deterministic matching, so `3 passed, 0 failed` and `passed: 3 failed: 0` read the same.
  - `failed>0` on any line, a FAIL word, or `NOT ok` is FAIL. Conflicting signals are `ERROR conflicting_summary`; zero tests is `ERROR zero_tests`; more passed+failed+skipped than the total is `ERROR inconsistent_counts`; a terminal SKIP word after passed tests is `ERROR`; only skips is SKIP.
  - Go units read `ok` / `FAIL` lines; a module with no `ok` line is `ERROR zero_tests`.
- Exit 0 with no recognised summary is PASS with `verdict_source=exit-code-only`; these are counted and listed separately and named in the RESULT line.
- Output beyond `--log-cap-mb` (default 64 MiB) is `ERROR log_overflow`. Output is streamed to the log through a pipe; only the last 1 MiB is kept in memory for the parser.

## Isolation

Each unit runs as `nice -n 15 ionice -c3 <runner> <path> [args]` in its own session, stdin `/dev/null`, with a clean environment: only `PATH LANG LC_ALL LC_CTYPE TERM USER LOGNAME TZ` come from the caller, plus any name given with `--env-extra NAME`. `HOME`, `TMPDIR` and the four `XDG_*` directories point into a fresh per-unit directory; `FULL_SUITE_UNIT_TOKEN` is a random per-unit token. Go units also get a fresh `GOCACHE`, the host `GOMODCACHE`, `GOFLAGS=-mod=readonly`, `GOPROXY=off`, `GOTOOLCHAIN=local`, `GOTELEMETRY=off`. Results record the variable names, never values.

After a unit ends (on timeout: SIGTERM to its process group, SIGKILL after 10 s; the group id is checked to be greater than 1, §11.4.263), every own-uid process whose environment still holds the token is killed and counted as leaked.

## Known failures

`config/full_suite_known_failures.tsv` lists OPEN failures only: path, signature (a literal substring of the unit log, or `reason:<code>`), tracked id, note. A failure is KNOWN only on an exact path match AND a matching signature. KNOWN is recomputed at every report from the CURRENT table and the unit log (whose sha256 is checked), never copied from an old record. The table is empty at this revision, so every failure fails the run.

## Results file and resume

`<out>/results.jsonl`, schema `fsr/3`. Each record carries a sequence number and the sha256 of the previous line (a hash chain from a zero genesis). A broken chain, a gap, a duplicate sequence number or an invalid record stops the runner (exit 2, "results integrity"); a torn LAST line (no newline, from an interrupted write) is dropped with a WARN. Each record has its own log file `logs/NNNNNN.log`. An exclusive lock on `<out>/.lock` stops a second runner on the same output directory (exit 2).

A record is reused only when its key matches: unit (path plus arguments), HEAD sha, working-tree hash, runner hash, and a context hash of the manifest bytes and the known-failures table bytes. The working-tree hash covers git status, `git diff HEAD`, untracked file contents, the status and diff of every submodule (recursively), and the names and content hashes of ignored files, except `__pycache__/`, `*.pyc`, `.pytest_cache/` and `qa-results/` (suites write evidence there). A resume never upgrades a verdict: when several records of one key disagree, the unit is `NONDETERMINISTIC` and the worst verdict counts. `--rerun-nonpass` re-runs recorded FAIL, TIMEOUT, ERROR and SKIP units.

## Usage

```
bash scripts/run_full_suite.sh --verify-manifest    # census + manifest check only
bash scripts/run_full_suite.sh --sync-guide         # rewrite the census line of this guide
bash scripts/run_full_suite.sh --list               # plan for the default mode, with the reason of every skip
bash scripts/run_full_suite.sh                      # default set (heavy units not run)
bash scripts/run_full_suite.sh --include-heavy      # full set: the §11.4.40 retest
bash scripts/run_full_suite.sh --only REGEX --timeout 300 --log-cap-mb 64
bash scripts/run_full_suite.sh --rerun-nonpass
```

Output goes to `${XDG_CACHE_HOME:-$HOME/.cache}/full_suite_runner/<repo>-<sha12>-<tree12>` unless `--out` is given; an `--out` inside the repository is refused. Progress: `wc -l <out>/results.jsonl` and the per-unit lines on stdout; final report in `<out>/summary.txt`.

## Exit status and RESULT line

| Exit | RESULT | Meaning |
|---|---|---|
| 0 | `PASS-FULL` | every unit ran, none skipped, nothing unexplained |
| 1 | `FAIL` | an unexplained FAIL, TIMEOUT, ERROR or NONDETERMINISTIC unit, or the repository tree changed during the run |
| 2 | | usage, configuration, results-integrity or lock error |
| 3 | `MANIFEST-MISMATCH` | census and manifest disagree, a rule is broken, the census is blind, or the census needle failed |
| 4 | `PARTIAL-NOT-RUN` | some units did not run (`--only`, interrupted) |
| 5 | `PARTIAL-DEFAULT-SET` | the default set is clean but heavy units did not run |
| 6 | `PARTIAL-SKIPS` | every unit ran and none failed, but at least one SKIPPED; the SKIPs are listed in summary.txt |

Exits 4, 5 and 6 end with `-- not a section 11.4.40 full retest`. Only exit 0 from a run with `--include-heavy` is a §11.4.40 full-suite retest.

## Limits

- The shell model is an approximation of bash. It does not follow `eval`, aliases, namerefs, indirect expansion, or command names computed at run time; such an entry needs its members declared as entries instead. A step budget stops a runaway loop with a parse error (exit 3).
- `verdict_source=exit-code-only` PASS units still allow `PASS-FULL`; they are counted and named, not hidden.
- Reading only the last 8 lines means a summary printed earlier and followed by more than 8 lines of output is not seen.
- `qa-results/` is not part of the tree hash, so a change there does not invalidate a resume record.
- Leak detection depends on the token staying in the environment; a process that cleared its environment and left the group is not found.
- A test can still pass while testing nothing; the runner checks what ran and what it reported, not the strength of each test.
