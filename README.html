The universal engineering constitution shared by every project that includes this repository as a Git submodule.

What this is

This repository contains the universal, project-agnostic rules, constraints, conventions and tooling that every Helix project (and any other project that opts in) inherits automatically. Project-specific rules live in the consuming project's own Constitution.md / CLAUDE.md / AGENTS.md / QWEN.md / GEMINI.md and extend what is in here.

The model is three-layer (top-to-bottom evaluation, project overrides universal when conflicts are explicit):

  1. Base layer (this submodule) — universal rules: the anti-bluff covenant (§11.4), data safety (§9), host safety (§12), test coverage, commit/push discipline, credentials handling (§11.4.10), documentation discipline (§11.4.65), submodule-catalogue-first discovery (§11.4.74), containers-submodule mandate (§11.4.76), release/QA gates, and the machinery (gates, validators, engines) that makes those rules mechanically checkable.
  2. Project layer — the project root Constitution.md / CLAUDE.md / AGENTS.md / QWEN.md / GEMINI.md: domain-specific rules, hardware-specific constraints, service-specific configuration.
  3. Subdirectory layer (optional) — <subdir>/CLAUDE.md for module-local overrides. CLI agents (Claude Code, Codex, Cursor, OpenCode, Qwen Code, Kimi CLI, Crush) merge these by walking up from the working directory.

Progressive-disclosure layer (progressive/)

Loading the whole canon into every agent turn is the measured root cause of repeated token exhaustion in consuming projects. The progressive/ tree splits the canon deterministically so an agent loads a lean core and pulls individual rules on demand. Constitution.md itself is untouched: every existing reader keeps working.

Real provider measurement (Claude Code 2.1.303, model sonnet, 24 frozen prompts, corpus SHA-256 5566abcc…): the progressive arm used 1,274,168 tokens against 7,168,066 for the monolithic arm — a ratio of 0.178 — at a measured cost of 0.6981 USD against 2.2808 USD, with 24 of 24 answers correct on the progressive arm against 22 of 24 on the monolith (progressive/EVIDENCE/TOKENS_AFTER.json, TOKENS_BEFORE.json). One host, one model, one corpus: these are measurements, not guarantees.

HELIX_CONSTITUTION_MODE selects the behaviour: progressive (default: core plus on-demand rules), dual (core plus full text available) or monolith (the exact pre-optimization behaviour — emergency rollback, no file needs reverting). HELIX_CONSTITUTION_PLUGIN=1 makes the skill defer to the plugin so the tools are never registered twice.

Open items, recorded in progressive/HANDOFF.md and progressive/EVIDENCE/DISCREPANCIES.md rather than glossed over: the literal "catalog at most 5,000 tokens" target is not met (the ids plus one-line descriptions alone measure 6,034 tokens); an AOSP sandbox comparison needs a real build; an independent fresh-clone sign-off is not yet committed; twin governance files reference 20 anchors the canon only cites, never defines (progressive/twin_exceptions.txt).

Decision layer (Jev)

Anchors §11.4.279–§11.4.286 add a typed-decision routing stage in front of the model ladder. A judgment that fits a typed decision (yes/no, choice, score) is answered by a small decision model ("Jev": hosted via TypeSafe/OpenRouter, or the local llmctl decide gateway; Kev, Laya, Verdict and Strands profiles are the other decision profiles) instead of a chat model, so only generative work spends traditional-LLM tokens. The §11.4.231 ladder itself is unchanged. The text lives in Constitution.md; the operator documents are under docs/jev/.

How to consume

1. Add the submodule

git submodule add git@github.com:HelixDevelopment/HelixConstitution.git constitution

# Pin to a release tag for reproducibility (recommended)
cd constitution
git checkout helixconstitution-v70
cd ..
git add constitution
git commit -m "chore: add Helix Constitution submodule pinned to helixconstitution-v70"

When teammates clone your project:

git clone --recurse-submodules <your-project-url>
# or if already cloned:
git submodule update --init --recursive

submodules/llmctl and submodules/claude_toolkit are the exceptions (recursive_init: false in helix-deps.yaml): initialise them one level deep only (git submodule update --init submodules/llmctl submodules/claude_toolkit), never with --recursive. llmctl no longer vendors this constitution (it resolves it, containers and superspec via lib/resolve_deps.sh), but it nests the third-party llama.cpp and colibri, which are never initialised recursively. claude_toolkit (pin 1f6dad3) no longer nests any own-org repository either — it resolves this constitution and its siblings flat via scripts/resolve_deps.sh and ships a tracked helix-deps.yaml — but it nests the third-party Go toolchain (submodules/go), which is never initialised recursively. Measured 2026-10-22: CM-HUB-ENGINE-NO-OWNORG-NESTING and CM-HELIX-DEPS-MANIFEST-PRESENT both PASS for every engine.

2. Wire the inheritance

Add a clearly-marked pointer at the top of your project's root CLAUDE.md:

## INHERITED FROM constitution/CLAUDE.md

All rules in `constitution/CLAUDE.md` (and the `constitution/Constitution.md`
it references) apply unconditionally. Project-specific rules below
extend them.

@constitution/CLAUDE.md

Same for AGENTS.md (any AI-agent tooling), QWEN.md and GEMINI.md:

> Base agent rules: `constitution/AGENTS.md` — READ IT FIRST.
> The base file is authoritative for any topic not covered here.

And for your project Constitution:

This constitution **extends** the Helix Universal Constitution at
`constitution/Constitution.md`. All clauses there apply unless
explicitly overridden below with an explicit `Override §X.Y`
section.

3. Keep always-loaded context small

Do not paste the canon into the files your agents load every turn — the measured cost of doing so is the reason the progressive layer exists. Keep the always-loaded files small, point at the rules, and let agents pull them on demand: progressive/core.md plus the MCP server (progressive/surfaces/mcp.json.template), or the helix-constitution skill and plugin. §11.4.141 (M2–M9) states the budget rules; the consumer enforces its own byte budget.

4. Set up the multi-upstream push

From the constitution submodule's root directory:

cd constitution
bash install_upstreams.sh

This reads every upstreams/*.sh declaration and configures matching git remotes locally, so a single git push origin reaches every provider.

5. Verify inheritance with an automated test

Every consuming project should ship a test that verifies the constitution submodule is present, at the expected pinned revision, and that the project's CLAUDE.md / AGENTS.md / QWEN.md / Constitution.md all reference it (the reference implementations are the ATMOSphere project's test_constitution_inheritance.sh and the Herald project's tests/test_constitution_inheritance.sh; this repository's meta_test_inheritance.sh proves the gate catches a deletion of the §11.4 anchor). A consumer that records the pinned commit in a .constitution-pin file must re-record it after every bump — progressive/validate_submodule.py compares that file with this repository's HEAD.

Versioning and releases

Contributing

Universal status has to be earned, not assumed. Project-specific content does NOT belong here. When in doubt, classify a rule as project-specific and keep it in the consuming project's own Constitution.

A rule is universal only if ALL are true:

  1. It would be true for at least 3 unrelated projects across different domains.
  2. It does not reference a specific service / schema / port / topic / table / vendor / hardware unique to one project.
  3. It encodes a policy or principle, not a configuration value.
  4. Removing it from any consuming project would be just as wrong as removing it from any other.

A rule is project-specific if any are true:

  • Mentions a specific service, package, topic, table, ML model, protocol version, hardware, or vendor.
  • Encodes a numeric threshold tuned for one codebase (coverage %, latency SLOs, retry counts).
  • Describes a workaround for a bug or quirk in a dependency this project uses.

A rule that lands without its enforcing seam is, by §11.4.227, a rule only in words: gate code is a separate work item, and the gate ledger (scripts/gates/gate_ledger_baseline.txt, deferrals in gate_ledger_deferrals.tsv) counts the debt and may only shrink.
