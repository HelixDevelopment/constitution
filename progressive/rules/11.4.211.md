Its SCOPE (every conflict-hitting main→feature/product/flavor merge) and its `xhigh` effort requirement stand; its Fable default and its Fable→Opus fallback ordering are withdrawn.

Any merge-CONFLICT resolution performed while integrating the canonical trunk (`main`/`master`) into a feature / product / flavor branch — the §11.4.188 regular main→feature merge cadence, the §11.4.195 branch-taxonomy integration, the §11.4.41 merge-first pipeline, the §11.4.167(D) trunk-into-stream sync AND the §11.4.167(I) approval-gated back-merge — MUST be carried out on the **Opus model at `xhigh` effort** as PRIMARY substrate. This is the merge-resolution analogue of §11.4.209 (which pins the same model + effort for code-REVIEW): §11.4.211 pins it for the DECISION-MAKING of conflict resolution (which side to keep, how to UNION both sides without loss, marker removal, semantic reconciliation of divergent edits). **(A) PRIMARY substrate Opus-xhigh + genuine-unavailability SONNET FALLBACK (amended 2026-10-04) — no Fable:** Opus at `xhigh` is the PRIMARY and preferred conflict-resolution substrate; Fable is NOT permitted in any role, ever, and no lower effort for Opus itself is acceptable. When Opus at `xhigh` is genuinely unavailable (not configured / rate-limited / unreachable, established as FACT per §11.4.6 — never a guessed unavailability), the conflict resolution MUST be carried out on **Sonnet** (at the highest effort the dispatch path can set) rather than blocked — the sole sanctioned fallback, per the verbatim 2026-10-04 operator mandate: resolve the conflict with whatever capable means are actually available, Opus ideally, Sonnet when Opus genuinely cannot be used; the Opus-unavailability FACT and the Sonnet-fallback substitution MUST both be recorded honestly in the merge's captured evidence (§11.4.5/§11.4.69) — a Sonnet-resolved merge is NEVER silently presented as if Opus resolved it. `xhigh` effort is REQUIRED on whichever substrate actually resolves the conflict WHERE THE DISPATCH PATH CAN SET IT — a careless conflict resolution silently drops a commit or commits a marker (§9 / §11.4.41 step 3), so the highest-effort scrutiny is mandatory regardless of model; where the dispatch path cannot set or report effort (the §11.4.231(F.2) harness gap), clause (D)'s honesty rule governs: the gap is recorded, never silently claimed as xhigh unverified. ONLY when BOTH Opus and Sonnet are genuinely unavailable (each established as its own captured FACT per §11.4.6, never guessed) is the conflict resolution BLOCKED and deferred: the unavailability fact is recorded, the merge is NOT completed, and the branch is left quiescent with no conflict marker committed (§11.4.84 / §11.4.41 step 3). **(B) Scope.** The operator named tracks 2–4 (`feature`/`product`/`flavor` branches); the rule GENERALISES per §11.4.17 to EVERY controlled main→(feature|product|flavor) merge on EVERY track that hits a conflict — the substrate requirement does not depend on which track. **(C) Safety preserved.** §11.4.211 sets the MODEL + EFFORT of the conflict-resolution work; it does NOT weaken and is BOUNDED BY the surrounding merge-safety invariants — §11.4.113 (NEVER force-push), §9 / §9.2 (no commit lost, hardlinked pre-op backup before any large/risky merge), §11.4.41 step 3 (ZERO conflict markers committed, ZERO file silently dropped, union of both sides preserved), §11.4.188(4) anti-bluff (post-merge smoke GREEN + conflict-marker scan empty + no-lost-commit, captured evidence §11.4.5/§11.4.69), §11.4.84 (quiescent-only), §11.4.37/§11.4.71 (fetch-first). **(D) Honest boundary (§11.4.6).** A merge whose conflicts were resolved on Fable or any model other than Opus or the sanctioned Sonnet fallback, or at an effort below `xhigh`, or on Sonnet with no recorded Opus-unavailability fact, is a §11.4 bluff at the merge-resolution-substrate layer — the merge's captured evidence MUST record which model + effort resolved the conflicts (and, when blocked, the FACT that both Opus and Sonnet were unavailable). Where the dispatch path cannot set or report the effort (the §11.4.231(F.2) harness gap), the evidence records that gap honestly and the merge is never claimed to have run at `xhigh` on an unverified basis. STRICT EXTENSION of §11.4.209 (which pins Opus-xhigh for code-REVIEW) applied to merge-CONFLICT resolution; STRENGTHENS §11.4.188 / §11.4.195 / §11.4.41 by pinning the substrate of their conflict-resolution step — the two anchors are the review-side (§11.4.209) and merge-side (§11.4.211) halves of the same Opus-xhigh-primary-plus-Sonnet-fallback substrate discipline.
