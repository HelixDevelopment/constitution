### §11.4.294 — Reproduction and investigation states are workable-item fields: every defect item carries a reproduction state and an investigation state from closed vocabularies, they gate the lifecycle transitions and the PROVISIONAL-DONE / VERIFIED-DONE levels, a regressed reproduction reopens the item, and every derived document and the external-tracker mirror QUOTE both states from the parent item and never retype them (User mandate, 2026-11-03)

**Forensic anchor — operator mandate (2026-11-03), as relayed by the conductor in the operator's words of intent (the operator's own message is not quoted here):** every document that is derived from, or links to, a workable item and quotes its status MUST also carry the reproduction state and the investigation state of that item, with the details behind them, wherever the information makes sense, and the values MUST be obtained from the parent workable item (the tracker database and the Issues / Fixed Markdown it renders).

**The gap this anchor closes (stated so it is not restated elsewhere, §11.4.227).** §11.4.292 makes the reproduction a recorded, closed-vocabulary RED carried by a `**Reproduction:**` line of the item body and requires the label `REPRODUCED` / `UNREPRODUCED` next to every other state label; §11.4.290 defines PROVISIONAL-DONE and VERIFIED-DONE. They leave four things open: (1) the record is prose, so no derived document, query or mirror can read it without parsing text; (2) the investigation (the root-cause half of §11.4.292(G)) has no recorded state at all, only the word `UNCONFIRMED:`; (3) neither says which STATUS TRANSITION needs which reproduction and investigation value; (4) neither says what a regression of the reproduction does to an item already past it. This anchor adds exactly those four and restates none of the others.

**(A) THE TWO FIELDS.** Two fields are added to every workable item. The §11.4.93 database is the single source of truth; the body lines are the human-readable mirror and the carrier of the details; the rendered Issues and Fixed documents, the per-item documents, the summaries, every derived document and the external tracker are generated from the database and never hand-edited (§11.4.106).

| Field | Where it lives | Vocabulary (closed, no seventh value) | Default | Written by |
|---|---|---|---|---|
| `reproduction_state` | column of the items table: `TEXT NOT NULL DEFAULT 'UNSET' CHECK (reproduction_state IN ('UNSET','UNREPRODUCED','reproduced-live','reproduced-host-fixture','not-reproducible-with-evidence','blocked-no-device-with-recorded-blocker'))` | `UNSET` · `UNREPRODUCED` · `reproduced-live` · `reproduced-host-fixture` · `not-reproducible-with-evidence` · `blocked-no-device-with-recorded-blocker` | `UNSET` | the workable-items engine only, from a command that carries the evidence path (clause (C)) |
| `investigation_state` | column of the items table: `TEXT NOT NULL DEFAULT 'UNSET' CHECK (investigation_state IN ('UNSET','not-started','in-progress','root-cause-found-with-evidence','root-cause-unconfirmed','closed-no-defect'))` | `UNSET` · `not-started` · `in-progress` · `root-cause-found-with-evidence` · `root-cause-unconfirmed` · `closed-no-defect` | `UNSET` | the same |
| `**Reproduction:**` body line | the item body | the §11.4.292(C) record line, unchanged; its first token maps to the column (clause (B)) | `none — UNREPRODUCED` (every `Bug`, per §11.4.292) | the worker, in the same commit or regeneration as the column |
| `**Investigation:**` body line | the item body | first token = `investigation_state` exactly, then one line of summary | `not-started` (every `Bug`) | the same |
| detail bullets | under the two body lines | `Symptom signature` · `RED` (command) · `RED evidence` (path) · `GREEN` (command) · `Rig needed` · `Missing` under Reproduction; `Root cause` · `Decisive experiment` · `Open` under Investigation | absent | the same |
| history | the item history, event type `Updated`, `reason` = `reproduction_state: <old> -> <new>` or `investigation_state: <old> -> <new>`, `evidence_path` = the capture that justifies the change | append-only | n/a | the engine |
| rendering | the Issues and Fixed item blocks carry the metadata lines `**Reproduction-State:** <value>` and `**Investigation-State:** <value>` next to `**Severity:**`; the Issues and Fixed summaries carry one column per field | the `md-to-db` / `db-to-md` round trip stays byte-identical (§11.4.93) | n/a | the engine |

A value is never typed twice: a body line whose first token maps to a different column value than the column holds is an integrity defect (two sources for one fact) and the validator FAILs it; the body line never overrides the column and the column never overrides the evidence (clause (C)). `UNSET` means NEVER ASSESSED: it is the default, the value of every item an audit did not cover, and PERMANENT and correct for an item outside the applicability of clause (E). `UNREPRODUCED` means assessed and no capture of the symptom exists (an attempt is possible or was never run). The two are different facts and a derived document never merges them.

**(B) VOCABULARY AND THE MAPPING TO §11.4.292.**

| `reproduction_state` | Meaning (quotable) | §11.4.292(B) result | §11.4.292 label |
|---|---|---|---|
| `UNSET` | never assessed | no `Reproduction:` record | `UNREPRODUCED` for a defect item (an item with no record is `UNREPRODUCED`) |
| `UNREPRODUCED` | assessed; no capture of the symptom exists; an attempt is possible or was never run | `none` | `UNREPRODUCED` |
| `reproduced-live` | a captured observation, on a running board or rig, of the symptom state or of the exact RED signature the fix must flip | `reproduced-live` | `REPRODUCED` |
| `reproduced-host-fixture` | a captured host RED (guard, test or command output) against a pre-fix artifact; never counts as live | `reproduced-host-fixture` | `REPRODUCED` when the record's surface is `host-only`, else `UNREPRODUCED` |
| `not-reproducible-with-evidence` | an attempt was made on the live target with a control needle, the capture is kept, and the symptom did not occur | `not-reproducible-with-evidence` | `UNREPRODUCED` |
| `blocked-no-device-with-recorded-blocker` | the blocker is hardware (phone, board, rig) and no earlier capture exists; a blocker record exists | `blocked-no-device-with-recorded-blocker` (the same spelling: the column value and the body token are one string) | `UNREPRODUCED` |

The body-token map used by every reader: `none` maps to the column value `UNSET` or `UNREPRODUCED`; every other body token IS its column value, spelled identically (`reproduced-live`, `reproduced-host-fixture`, `not-reproducible-with-evidence`, `blocked-no-device-with-recorded-blocker`). **ONE SPELLING of every state.** The stored column value, the body token, the history text, every derived document and the tracker mirror print the long form `blocked-no-device-with-recorded-blocker`, which is the spelling of §11.4.292(B); the short form is an alias that is read and never written (input alias only: `blocked-no-device`): a command-line flag value or an import-file cell may carry it, the engine normalises it to the long form before anything is stored, and it is never stored, never rendered and never a closed-set head of a `**Reproduction:**` body line (a body line that starts with it is a validator problem, not a state). A derived document that prints the §11.4.292 LABEL for `reproduced-host-fixture` MUST read `surface` from the body record; the column alone does not decide that label. A derived document that prints only the STATE names the vocabulary, never the label.

| `investigation_state` | Meaning (quotable) | §11.4.292 anchor |
|---|---|---|
| `UNSET` | never assessed | n/a |
| `not-started` | assessed; no investigation has begun | before (G) |
| `in-progress` | an investigation is running and no root cause is confirmed yet | (G), §11.4.102 |
| `root-cause-found-with-evidence` | the root cause is established as FACT: a causal chain whose every link carries captured evidence, closed by a decisive experiment that toggles the signature by toggling the cause | (G) |
| `root-cause-unconfirmed` | a hypothesis exists and the evidence that would confirm it is missing; it is written `UNCONFIRMED:` wherever it is quoted (§11.4.6) | (D)(3), (G) |
| `closed-no-defect` | the investigation concluded there is no defect, and the capture of that conclusion is cited | (F) |

**(C) EVIDENCE FOR A STATE CHANGE — evidence that is gone is not evidence.** A state is a claim and a claim needs captured evidence (§11.4.6, §11.4.69). The engine accepts a write of a value other than `UNSET`, `UNREPRODUCED` or `not-started` only together with an evidence path and its sha256 that exist, and it appends the history event of clause (A) in the same transaction. `reproduced-live` and `reproduced-host-fixture` need the §11.4.292(C) RED record (command, captured output, build, target identity, symptom signature). `not-reproducible-with-evidence` needs the attempts and the control needle (§11.4.292(F)). `blocked-no-device-with-recorded-blocker` needs the blocker record (WHAT, WHY with every self-resolution path tried, UNBLOCK CONDITION, WHO, §11.4.21). `root-cause-found-with-evidence` needs the decisive-experiment capture. `closed-no-defect` needs the capture that shows the absence. If the evidence path of a state no longer resolves, or its sha256 differs, the state is demoted in the next regeneration: `reproduced-*` to `UNREPRODUCED`, `root-cause-found-with-evidence` to `root-cause-unconfirmed`, and `blocked-no-device-with-recorded-blocker` keeps only while the blocker record resolves. The demotion is a history event with reason `evidence lost` and is shown by every derived document. Evidence for a state MUST be stored under a tracked or custody-backed path (§11.4.210), not only under an untracked, gitignored or otherwise non-durable evidence store.

**(D) THE LIFECYCLE TRANSITIONS AND THE GATE OF EACH.** Statuses are the closed set of §11.4.15 / §11.4.21 / §11.4.90; this anchor adds no status word. "Defect item" is defined in clause (E). A "fix commit" is a commit that claims to address the item.

| # | Transition | `reproduction_state` required | `investigation_state` required | Notes |
|---|---|---|---|---|
| T1 | create a defect item | `UNSET`, with `**Reproduction:** none — UNREPRODUCED` in the body | `UNSET` or `not-started`, with `**Investigation:** not-started` | the item template writes both lines for every `Bug` |
| T2 | `Queued` to `In progress` | none at entry; the FIRST work act is the live reproduction (§11.4.292(A)) | none at entry | the first status write after the first attempt sets the states; `UNSET` never survives it for a defect item |
| T3 | any fix commit | `reproduced-live`, `reproduced-host-fixture` or `blocked-no-device-with-recorded-blocker`; NOT `UNSET`, `UNREPRODUCED` or `not-reproducible-with-evidence` (no fix against a symptom never observed, §11.4.292(F)) | `root-cause-found-with-evidence` when the reproduction is `reproduced-*`; `root-cause-found-with-evidence` or `root-cause-unconfirmed` only when the reproduction is `blocked-no-device-with-recorded-blocker` (§11.4.292(D)(3): the root-cause claim is written `UNCONFIRMED:`) | a fix before the root cause is investigated is the §11.4.102 violation this row repeats; `in-progress` is not enough to land a fix |
| T4 | `In progress` to `Ready for testing` / `In testing` (PROVISIONAL-DONE, §11.4.290) | the same set as T3 | the same set as T3 | plus the §11.4.290 conditions (implemented, wired, verification job scheduled); the item is labelled `PROVISIONAL-DONE` and, where clause (B) says so, `UNREPRODUCED` (for example `PROVISIONAL-DONE, UNREPRODUCED`); when the reproduction is not `reproduced-live`, the FIRST step of the scheduled job is the live RED on the pre-fix artifact (§11.4.292(D)(2)) |
| T5 | PROVISIONAL-DONE to a closure value (VERIFIED-DONE: `Fixed` / `Implemented` / `Completed`) | `reproduced-live`; or `reproduced-host-fixture` with surface `host-only` | `root-cause-found-with-evidence` | plus the §11.4.292(E) pair (same command, same target, same signature), the §11.4.292(G) live coverage test and every other closure seam; NOT reachable with `UNREPRODUCED`, `UNSET`, `blocked-no-device-with-recorded-blocker`, `not-reproducible-with-evidence` or `root-cause-unconfirmed` |
| T6 | any open status to `Reopened` | the state the contrary evidence supports (clause (F)) | the state the contrary evidence supports (clause (F)) | contrary evidence per §11.4.290(D); `Reopened-Details` per §11.4.34 |
| T7 | `In progress` to `Operator-blocked` | `blocked-no-device-with-recorded-blocker` is the usual value; the blocker record MUST resolve | any | §11.4.21: a last resort with WHAT / WHY / UNBLOCK CONDITION / WHO; a hardware blocker for the reproduction alone does NOT need the status, the fix may land provisionally (T3, T4) |
| T8 | to `Obsolete` with reason `not-reproducible` | `not-reproducible-with-evidence` | `closed-no-defect` | §11.4.292(F): the only closure a `not-reproducible-with-evidence` item has; any other §11.4.90 reason leaves the states as the evidence supports them, and no state is set to satisfy the reason |
| T9 | a non-defect item (clause (E)) | `UNSET`, permanently | `UNSET`, permanently | no gate applies; `UNSET` is correct and the validator accepts it |

A transition that fails its row is refused by the engine (exit non-zero, the status is not written) and, for an item already past it, is reported as `STATE-GATE` in every derived document and in the next changelog. **Existing items: no silent demotion, no free pass.** Items that were PROVISIONAL-DONE before this anchor and do not meet T4 keep their status (optimistic done, §11.4.290: nothing is demoted without contrary evidence); they carry the label `UNREPRODUCED` or the state value `UNSET`, are listed as reproduction debt in every roadmap and changelog, and the first step of their verification job is the live reproduction (§11.4.292(D)).

**(E) APPLICABILITY.** The two states describe a DEFECT. They apply to an item of Type `Bug`, and to a `Task` or `Feature` whose closure claims that a defect was removed (the §11.4.292(A) scope). They do not apply to a `Feature` that requests a capability, to a deployment, build, flash or documentation `Task`, to a verification-only `Task`, or to an investigation `Task` with no defect symptom: for those items both states stay `UNSET` forever (row T9), and a derived document prints `UNSET` and counts the item separately from the unaudited defect items wherever it can tell the types apart. An item is moved INTO the applicable set only by an edit of its Type or of its closure claim, in the same transaction as the first state write.

**(F) PROVISIONAL-DONE VERSUS VERIFIED-DONE, AND THE REOPEN RULE WHEN THE REPRODUCTION REGRESSES.** The matrix for a defect item ("fix may land" is row T3; "highest done level" is the highest the item may reach while the combination holds):

| `reproduction_state` | Fix may land | Highest done level | Label | Needs from `investigation_state` |
|---|---|---|---|---|
| `UNSET` | no | none (`In progress` at most) | `UNREPRODUCED` | n/a |
| `UNREPRODUCED` | no | none | `UNREPRODUCED` | n/a |
| `reproduced-live` | yes | VERIFIED-DONE | `REPRODUCED` | `root-cause-found-with-evidence` |
| `reproduced-host-fixture`, surface `host-only` | yes | VERIFIED-DONE | `REPRODUCED` | `root-cause-found-with-evidence` |
| `reproduced-host-fixture`, surface `live-target` | yes | PROVISIONAL-DONE | `UNREPRODUCED` | `root-cause-found-with-evidence` |
| `blocked-no-device-with-recorded-blocker` | yes, only provisionally | PROVISIONAL-DONE | `UNREPRODUCED` | `root-cause-found-with-evidence` or `root-cause-unconfirmed` (written `UNCONFIRMED:`) |
| `not-reproducible-with-evidence` | no | none; closes only by T8 | `UNREPRODUCED` | `closed-no-defect` for the T8 closure; `in-progress` while the conditions are widened |

PROVISIONAL-DONE is never called verified, fixed or passing, never a row of Fixed, never in a verified count (§11.4.290). Every report prints "V verified + P provisional (O overdue)" and, beside the provisional count, how many of the P carry the label `UNREPRODUCED`. A `root-cause-unconfirmed` investigation state is a hypothesis; a report that quotes it writes `UNCONFIRMED:` in front of the cause. Three situations touch an item already past its reproduction, and only the first is contrary evidence.

1. **The symptom is observed again after the fix (the reproduction regresses).** A run of at least the layer's evidence class that reads the §11.4.292 symptom signature TRUE on an artifact whose fingerprint equals the fix's artifact fingerprint, on the same target identity, from an instrument proven by its control needle, is the §11.4.290(D) contrary evidence. The item is `Reopened` with `Reopened-Details` (reason `test-failed` or `captured-evidence-contradicts`; evidence = that run) and, in the same transaction, `reproduction_state` becomes `reproduced-live` (or `reproduced-host-fixture` when the observation was on a host fixture) with the new RED record appended and the earlier GREEN kept in the history, and `investigation_state` becomes `in-progress` (the earlier cause was not sufficient) or `root-cause-unconfirmed` (the capture contradicts the earlier cause itself; the old claim stays in the history, marked superseded). The reopened item meets T3 and T4 again before it can be provisional or verified again, and the reopens count increments, with the §11.4.189 extra-scrutiny priority that follows it (§11.4.290(D)). The reopen is recorded as `**Reproduction-Regress:** reproduction_state <old> -> <new> — signature TRUE on artifact <fingerprint> (fix artifact <fingerprint>) — target <identity> — red <path> sha256 <hash>` and `**Investigation-Regress:** investigation_state <old> -> <new> — earlier cause <one line> now <superseded | contradicted: evidence <path>>`.
2. **The state is demoted because its evidence is gone (clause (C)).** This is not contrary evidence (§11.4.290(D): absence of evidence, a wrong target, a BLIND instrument and a lower class are never contrary evidence). A PROVISIONAL-DONE item keeps its status and carries `UNREPRODUCED`; its job's first step re-captures the RED. A VERIFIED-DONE item keeps its closure value, but the combination (closure, `UNREPRODUCED`) is printed `INCONSISTENT — red evidence lost` in every derived document and a `Task` is filed to restore the capture from backup or to rebuild the pre-fix artifact and re-run the RED (§11.4.210); the status is changed only by a decision of the conductor.
3. **A `not-reproducible-with-evidence` item is reproduced later.** The state becomes `reproduced-live`; an item closed `Obsolete (not-reproducible)` is reopened (reason `cycle-re-discovered` or `manual-testing-detected`) with the new RED as its evidence; `investigation_state` leaves `closed-no-defect` for `in-progress`.

A VERIFIED-DONE closure carries `**Closure-Record:**` with three lines: the final reproduction (state, red path + sha256, green path + sha256, same command / same target / same signature each `yes`), the final investigation (`root-cause-found-with-evidence`, one-line cause, evidence path) and the live coverage test (path, determinism N of N identical verdicts, control needle path, registered guard path).

**(G) A STATE CHANGE IS NOT A STATUS CHANGE.** Writing `reproduced-live` does not move an item out of `Queued`; writing `root-cause-found-with-evidence` does not mark it done. The Status closed set is not extended (the rule §11.4.290 and §11.4.292 follow).

**(H) PROPAGATION TO DERIVED AND LINKED DOCUMENTS.** Every document that quotes the status of a workable item carries the two states of the PARENT item where it makes sense, READ from the database (the Markdown the engine renders is the same data). A derived document never decides, retypes or defaults a state; where the database cannot be read it prints `UNCONFIRMED` (§11.4.6), not `UNSET`.

| Document class | Carries the states | How |
|---|---|---|
| a per-item table (roadmap row pages, per-row lists, changelog per-row tables, summaries) | yes | two plain columns at the END of the table (existing column positions do not move; the columns are never a sort key) |
| a document that lists items with a label per reference (labelled analysis documents) | yes, once per document | one derived table of the referenced defect items; the label group on each reference is not extended |
| a document that counts items (roadmap numbers-only cell, burndown, progress counters) | no | a count is a count of status; mixing a second vocabulary into a numbers-only cell breaks its contract and every parser of it; the per-row pages carry the per-state counts one level down |
| a generator input that is itself the source of a status token | no | the token is synchronised FROM the tracker; adding the states there creates a second source |
| a verification schedule (PROVISIONAL jobs) | in the job note only | the job's first step is the live RED when the state is not `reproduced-live` (T4); the schedule format is not extended with a column |
| a release changelog | yes, in the per-row testing tables of the NEXT release | one added column; a published changelog is a historical record and is never rewritten |
| an auto-generated log of agent dispatches or a request history | no | they record events, not item state |

The consuming project lists its concrete documents as DATA (§11.4.35). Enforcement for every generator follows one pattern: a generator reads the oracle (the database columns), an INDEPENDENT gate re-derives the expectation from the same oracle and shares no code with the generator, and each new behaviour has a paired mutant that the gate kills.

**(I) THE SYNC CONTRACT TO THE EXTERNAL-TRACKER MIRROR.** The database is the single source (§11.4.93); the external tracker (§11.4.148 D5) is a one-way mirror for these fields. (1) Direction: database to tracker only; an edit of the fields on the tracker side is overwritten by the next push and reported as drift, it never flows back. (2) Representation: two description header lines under the status header, `**Reproduction-State:** <value> (<REPRODUCED|UNREPRODUCED>)` and `**Investigation-State:** <value>`, the label printed only when clause (B) lets the pusher derive it; two tracker tags `repro:<value>` and `investigation:<value>` for filtering, the pusher removing the old tag of the same prefix before it adds the new one; custom fields of the same names ONLY if the tracker list defines them, the pusher never creating a field (the §11.4.112 API-cannot-create constraint of §11.4.148 D5). (3) Details travel inside the item description the pusher already sends; there is no second channel. (4) Matching and idempotence follow §11.4.148 D5 (match by the stable key, present means UPDATE, absent means CREATE); the §11.4.86 fingerprint is extended with the two state values per item, so a state change alone triggers a push and an unchanged state does not. (5) Proof: every push captures the sink-side `created=N updated=M failed=0` line (§11.4.69) and, for these fields, reads back the description header and the tags of a sample of at least three items that differ in state and compares them with the database; offline the mirror is `UNCONFIRMED`, never `PASS`. (6) Failure: an unreachable tracker or a failed push leaves the database and every derived document correct; the mirror is reported stale with the failed item ids; a mirror value that disagrees with the database is a defect of the mirror, not of the database. (7) Round trip: `md-to-db` reads the two `**…-State:**` metadata lines of the rendered blocks back into the columns and rejects a value outside the vocabulary.

**(J) WHAT THIS ANCHOR DOES NOT CHANGE.** §11.4.6, §11.4.15, §11.4.21, §11.4.33, §11.4.34, §11.4.90, §11.4.102, §11.4.115, §11.4.146, §11.4.199, §11.4.289, §11.4.290 and §11.4.292 keep their full text. This anchor adds two tracker fields, the transition gates that use them, the regression rule and the propagation and mirror contracts. It does not prove that any item carries a correct record: a reproduction proves that the symptom existed under the recorded conditions, and it does not prove the root cause, which the investigation state records separately.

**Honest boundary (§11.4.6).** The gate shipped with this anchor proves the RULE is present exactly once, complete, mirrored in the four context carriers, indexed and generated into the group, rule file and catalog, and that the shipped item template (`scripts/reporting/report_item.sh`) and the two workable-item skills carry the `Investigation:` field and the transition table. It does NOT prove that any item carries a correct state, that a transition was gated, that a derived document quotes the parent item, or that the mirror agrees with the database: those item-level seams are the recommended gates `CM-STATE-FIELDS-LIFECYCLE`, `CM-STATE-PROPAGATION` and `CM-STATE-TRACKER-MIRROR`, registered as deferrals `OWED-GATE-177`, `OWED-GATE-178` and `OWED-GATE-179` and NOT claimed implemented (§11.4.227(A)). The workable-items engine in this repository does not yet implement the two columns, the validator rules of clause (D) or the mirror of clause (I): that is consuming-project and engine work.
