### §11.4.295 — Substitute app, same verdict: when a content API is geo-restricted the refusal is recorded as GEO_RESTRICTED and the SAME test runs with a substitute app under the SAME pass/fail criteria; the restriction is never reported as a failure and never lowers the bar (User mandate, 2026-11-03)

**Forensic anchor — operator ruling (2026-11-03), "Substitute app, same verdict", as relayed by the conductor in the operator's words of intent (the operator's own message is not quoted here):** when a content API is geo-restricted, record `GEO_RESTRICTED`, run the same test with a substitute app, and apply the same pass/fail verdict criteria — never report the restriction as a failure, never apply weaker criteria.

**The gap this anchor closes (stated so it is not restated elsewhere, §11.4.227).** §11.4.3 lets a topology or geo block end a test as a SKIP-with-reason; §11.4.69 closes the SKIP reason set with `geo_restricted`; §11.4.107(3) turns "timeout and the content endpoint unreachable" into a SKIP-with-reason; §11.4.117 and §11.4.143(5) list geo-unreachable content among the genuine-infeasibility SKIPs; §11.4.293(C) counts a baseline-PASS test that is SKIPPED on the new image as `baseline-pass-lost`, and the 2026-11-03 changelog entry of §11.4.293 recorded the clash with a consuming project's "a geo restriction is never a failure" rule as an open question. None of them (1) says what the tester does AFTER the refusal, so a SKIP silently drops the coverage of the very platform path the test exists to prove; (2) fixes the criteria a replacement run is held to; (3) separates a geo refusal from a general outage by captured evidence; (4) says how the image comparison of §11.4.293 sees a replacement run. This anchor adds exactly those four and restates none of the others.

**(A) THE PROBE AND THE RECORD.** Before a test plays or fetches content through an app, the app's content API is probed, on every run, from the run's own egress, never from a remembered earlier result. A refusal is `GEO_RESTRICTED` only when ALL hold: (1) the probe result carries a refusal signature from the consumer's declared closed list (default: a timeout, HTTP 403, HTTP 451, a refused connection, a region-block page; DATA, §11.4.35); (2) a control probe from the SAME egress in the same window to a declared reachable control endpoint succeeds, otherwise the cause is an outage and the outcome is `network_unreachable_external`, never `GEO_RESTRICTED`; (3) the record is captured: app id, endpoint, refusal signature, status or timeout value, timestamps, egress identity (region or VPN state) and the control probe result. A refusal without that record is an instrument failure (INCONCLUSIVE, §11.4.201), never a `GEO_RESTRICTED` and never a PASS. The record label is `GEO_RESTRICTED`; the SKIP reason code `geo_restricted` of §11.4.69 is unchanged.

**(B) SUBSTITUTE APP, SAME TEST.** After a recorded `GEO_RESTRICTED` the SAME test (same test id, same steps, same oracles, same thresholds, same observation windows, same run count) runs with a substitute app taken from the substitute chain that the consumer declared in advance for the test's capability class (DATA, §11.4.35): an app that exercises the same platform path the test is about (the same content class, routing target and decode, render and audio path). The chain is declared BEFORE the run, ordered, and is never chosen after a result is seen; every candidate is probed per clause (A), and a candidate that is itself `GEO_RESTRICTED` is recorded and passed over for the next. The substitute is a different APP, never a different test: no step is dropped, no oracle is relaxed, no window is shortened. The substitute is a real app on the real target (§11.4.289), never a stub.

**(C) SAME VERDICT.** The substituted run is held to the SAME pass/fail criteria. The test's criteria set (its oracles, thresholds, windows and run count) is identical to the one the original app would have been held to; both runs record the sha256 of that criteria set and the two MUST be equal. The substitute run's verdict is the test's verdict: `PASS` when the criteria are met, `FAIL` when they are not (a real defect in the shared platform path stays a failure), and the usual closed set otherwise (§11.4.293(B)). `GEO_RESTRICTED` itself is never reported as a failure, never a PASS, and never the final verdict of a test while a probed-reachable substitute exists. Weaker criteria for a substitute (a lower threshold, a shorter window, a skipped oracle, a smaller run count, a different pass condition) is a PASS-bluff at the criteria layer.

**(D) THE REPORT.** The test line names both apps and the outcome, `GEO_RESTRICTED(<original app>) -> <substitute app>: <verdict>`, and the evidence holds both app identities, both probe records and both criteria hashes. A substituted run proves the platform path the test is about; it does NOT prove the restricted app's own behaviour (its UI, sign-in, catalog, entitlement, DRM), and no report says it does. A test whose SUBJECT is the restricted app itself has no substitute by definition: it keeps the §11.4.3 outcome (SKIP-with-reason `geo_restricted`, never a PASS, never a FAIL), is tracked as an item (§11.4.202) and is cured only by running it where the app is reachable.

**(E) EXHAUSTED CHAIN.** When every candidate of the chain is `GEO_RESTRICTED`, or the capability class has no declared substitute, the outcome is the §11.4.3 SKIP-with-reason `geo_restricted`: never a PASS, never a FAIL. It is reported together with the chain it exhausted and tracked as an item (§11.4.202). This anchor does not extend the operator ruling beyond a reachable substitute.

**(F) INTERACTION WITH §11.4.293.** A substituted run is a verdict-bearing run of the same test id (it is neither absent nor SKIPPED), so it enters the image comparison with its verdict, and the per-test diff records both app identities when they differ between the baseline run and the new run. An exhausted chain, or an app-specific test, that is SKIPPED where the baseline was PASS is `baseline-pass-lost` by §11.4.293(C); the constitution does not relabel it, and it is cured by running the test where the app is reachable. The open question recorded for the consuming project in the §11.4.293 changelog entry is thereby answered: the "never a failure" rule is kept and is met by a substituted verdict, not by a SKIP.

**(G) WHAT THIS ANCHOR DOES NOT CHANGE.** §11.4.3 (the SKIP-with-reason outcome), §11.4.69 (the closed SKIP reason set, `geo_restricted` included), §11.4.107, §11.4.117, §11.4.136, §11.4.143, §11.4.201 (a BLIND or INCONCLUSIVE instrument), §11.4.289 and §11.4.293 keep their full text; this anchor adds the probe record, the substitute-first rule, the same-criteria rule and the report line. The Status closed set and the verdict sets are not extended.

**Honest boundary (§11.4.6).** The gate shipped with this anchor proves the RULE is present exactly once, complete, mirrored in the four context carriers, indexed and generated into the group, rule file and catalog, and wired into the seams that carry rules. It does NOT prove that any test probes first, that any substitute chain is declared, that the two criteria hashes are equal, or that a substituted run exercised the same platform path: that item-level seam is the recommended gate `CM-GEO-SUBSTITUTE-SAME-VERDICT`, registered as deferral `OWED-GATE-180` and NOT claimed implemented (§11.4.227(A)). The control probe bounds, and does not eliminate, the chance that a refusal is a defect of the app or the network rather than a region rule (§11.4.118).
