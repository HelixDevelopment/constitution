### §11.4.291 — Capacity-aware decision-model placement: a local decision model runs only when the host's LIVE load leaves room for it; otherwise decision traffic falls back, visibly and with a recorded reason, to the hosted endpoint when its key is present (or to a reasoned absence when it is not); the placement is re-evaluated at any time, including while a model runs; the constitution starts and stops llmctl models on demand and never enables them for boot (User mandate, 2026-10-28)

**Forensic anchor — verbatim operator mandate (2026-10-28), mandate (1):** "If host is not powerful enough to work with local decision model in parallel with current work load of the same host, then user has to be informed and use of the locally run decisions model switched to cloud provider such as Jev (if api key is available)! We MUST BE aware that certain hosts can or cannot deal with its current work load (CLI agents we use and sessions we have) + decisions model being executed! This MUST BE smooth and dynamic and the constitution MUST be extended to determine the load, the capacity and if and which exactly decision model can fit and run without issues! We MUST NOT get into any OOM or similar situations!" Two further mandates of the same day, relayed by the conductor and NOT verbatim: (2) llmctl local models must never take all CPUs or all RAM; a reserve always stays free for the system; (3) the constitution uses llmctl only when needed — start and stop on demand, never `enable` triggered by the constitution; `enable` (start at boot) is a separate operator choice only, and the system must never hang.

**The gap this anchor closes (stated so it is not restated elsewhere, §11.4.227).** §11.4.282(A) computes decision capacity from `llmctl plan --json` `decision_instances` and §11.4.277(E)(3) refuses an engine start under memory pressure. Neither decides, BEFORE the decision layer routes traffic, whether a local decision model fits NEXT TO the host's current work (the agent sessions, builds and other services already running), neither tells the operator when it does not, neither defines the switch to the hosted endpoint, and none says who may start, stop or enable a model. A pressure refusal at start time is the last line; this anchor is the line in front of it.

**(A) PLACEMENT VERDICT — closed set, per decision profile, in llmctl's own words.** Before a decision profile is started, before decision traffic is routed to a local instance, and at every re-evaluation of clause (D), the project MUST obtain a placement verdict for each candidate profile from the closed set `{fits, fits_with_reduced_threads, does_not_fit, undetermined}`. The first three are the verdict names `llmctl capacity --json` emits (schema `llmctl.capacity/1`, contract table in clause (C)); `undetermined` is NOT an llmctl verdict: the consumer derives it, by the rules of clause (C), when the capacity source gives no usable answer. `fits` — the profile at its declared configuration (full CPU cap and memory limit) fits next to the live load with the host reserve of clause (B) intact; `fits_with_reduced_threads` — memory fits, but fewer CPUs than the profile's cap are left (at least one); the thread count the source reports in `threads` is recorded and is the configuration that is started (llmctl's own start applies the same reduced cap and can only lower it); `does_not_fit` — memory, CPU, the planner or current pressure say no; `undetermined` — see clause (C). llmctl also reports `running` for a profile that is already running: that is not a verdict for a start; the running instance is judged by its unit `status` (`ok` keeps it eligible for routing, `degraded` is treated as `does_not_fit` for that instance and triggers clause (D)(1)). `undetermined` is NEVER read as `fits` (§11.4.201(4), §11.4.6): for a start it is treated exactly as `does_not_fit`, except through the explicit override of (A.1).

**(A.1) OPERATOR OVERRIDE OF `undetermined` — explicit, recorded, never silent; never of `does_not_fit`.** While no live capacity source is vendored, `undetermined` keeps constitution automation from starting a local decision model on every host. The operator MAY lift that for a start of a named profile on a named host by exactly one of: (1) a §11.4.271 waiver (rostered non-producer authoriser, unelapsed expiry, tracked item) naming the host and the profile; or (2) a recorded operator attestation, written into the placement entry as `override: "<id>"`, where `<id>` resolves to a recorded operator decision (§11.4.66) naming the host, the profile and an expiry. The placement entry keeps `verdict: "undetermined"` and adds the override id; the clause (F) notice names the override at every start it permits. An override with no resolvable id, or past its expiry, is not an override. An override never lifts `does_not_fit`, never lifts the §11.4.277(E)(3) pressure gate (llmctl's start gate still runs, and its refusal with exit 75 is `does_not_fit` for that round), and never lifts clause (G). ROUTING TO AN ALREADY-RUNNING INSTANCE under `undetermined`: an instance the operator started (not constitution automation) MAY receive decision traffic without an override, because routing adds no resident footprint; the route is recorded with `verdict: "undetermined"`, reason `operator-started instance`, and a clause (F) notice. If that instance reports `degraded` or stops answering, traffic moves per (D)(1) and (J)(6). The constitution never starts a second instance on that basis.

**(B) HOST RESERVE — the model never takes the whole host (mandate (2)).** The verdict is computed against a budget that leaves a reserve the model can never use: (1) RAM: the model's footprint plus everything already resident must fit the live budget with the reserve intact, and a decision model counts against the §12.6 ceiling like every other project procedure; the §11.4.277(E)(3) start gate (footprint plus its reserve against `MemAvailable`, memory PSI thresholds) still applies on top and is never relaxed; (2) CPU: the model's thread count leaves cores to the work already running, and interactive degradation is diagnosed with the §11.4.225 throttle accounting, never with load averages alone; (3) threads and processes: the model's threads fit the §12.12 `RLIMIT_NPROC` headroom; (4) GPU: VRAM is budgeted the same way where the profile uses it. The reserve sizes are host-adaptive and are consumer DATA or llmctl reference values (§11.4.35, §12.11); this anchor sets no new number. Making the engine itself keep that reserve (thread count, CPU quota and memory caps of the unit) is llmctl's job (§11.4.277(E)); this anchor requires that whatever the constitution starts has passed a verdict that accounts for it.

**(C) INPUT CONTRACT — measured, live, with provenance.** The verdict reads, at decision time and for the host and the cgroup scope the model would run in: `MemTotal` and `MemAvailable`; memory PSI `some` and `full`; CPU PSI and the load average against the online CPU count; the scope's `memory.max`, `memory.current`, `cpu.max` and the throttle counters of §11.4.225 where the scope has them; the RAM, thread and CPU footprint of every llmctl profile already running; the candidate profile's footprint; the `RLIMIT_NPROC` headroom; and the reserve values used. Every input carries its source and its timestamp; a value that could not be read is recorded as unreadable, never defaulted (§11.4.6). The canonical source is `llmctl capacity --json`, under this contract:

| Field of schema `llmctl.capacity/1` | Required | Use under this anchor |
|---|---|---|
| `schema` | yes; must equal `llmctl.capacity/1` | absent or any other value: `undetermined` (a newer schema is adopted only by amending this table) |
| `time` | yes | the measurement time (Unix seconds); recorded as the timestamp of every input taken from this document |
| `profiles.<p>.verdict` | yes, for every candidate | `fits` / `fits_with_reduced_threads` / `does_not_fit` / `running`; any other value: `undetermined` |
| `profiles.<p>.threads`, `.reasons`, `.headroom` | yes | the thread count to start, and the deciding inputs recorded per clause (F) |
| `host` (memory, swap, load, `psi`, `cgroup`), `reserve`, `pressure` | yes | the measured inputs and the reserve used, recorded with source `llmctl capacity` and the `time` value; schema 1 has no single `measured` object, these three ARE the measurement |
| `llmctl.units[]` (`profile`, `status`, `reasons`) | yes | running engine units; `status: degraded` drives clause (D)(1) |
| `fallback.recommended` | yes | `local` / `cloud` / `none`: the route of clause (E) |
| `fallback.key_variable` | yes (null allowed) | the NAME of the hosted-key variable llmctl found set; never a value |
| `unknown_profiles`, `degraded`, `largest_decision_fit` | yes | a candidate listed in `unknown_profiles` is `undetermined` for that candidate |

Exit statuses of `llmctl capacity --json [profile...]`: `0` every named profile fits (or, when none is named, no running unit is degraded); `75` a named profile does not fit or is unknown; `3` no profile named and a running llmctl unit is degraded. Exit `75` and exit `3` with a parseable document are normal answers: the document's verdicts are used. The consumer derives `undetermined` (for every candidate, or for the one candidate concerned) when: the exit status is any other value (llmctl's own measurement failure included); llmctl is absent or older than the version that provides the command; the call exceeded its bounded timeout (clause (G)); the output is not one parseable JSON object; `schema` is absent or different; a required field of the table is absent or holds a value outside its set; or an input this anchor requires and the source does not supply could not be measured (below). Schema 1 does not carry the `RLIMIT_NPROC` headroom nor the §11.4.225 `cpu.stat` throttle counters: the consumer measures the `RLIMIT_NPROC` headroom itself with a documented, tested script (§11.4.274), and an unmeasured headroom makes the verdict `undetermined` for a start; the throttle counters serve the clause (B)(2) diagnosis of interactive degradation, are recorded as `not_supplied` when absent, and do not by themselves block. llmctl detects a hosted key by presence (non-empty) only: before routing to `cloud` the consumer still applies the §11.4.279(E) non-placeholder check by variable NAME, and a placeholder key turns `cloud` into `none`. Provenance (§11.4.6): the field names, verdict names and exit statuses above were read on 2026-10-28 from the llmctl 3.4.0 working tree (`lib/capacity.sh`, `docs/capacity.md`), which was uncommitted and still being edited, and one run of `llmctl capacity --json` from that tree on one host returned `schema` `llmctl.capacity/1` with exit 0 and these top-level keys; nothing is vendored. The contract binds as "schema `llmctl.capacity/1`"; a rename before llmctl 3.4.0 is tagged and vendored is absorbed by amending this table, never by guessing a field. Measured fact about the current pin (llmctl 3.3.2, commit `11a9154`, `lib/catalog.sh` lines 1-12 and 365-400): `llmctl decide capacity --json` returns `tier`, `budgets` and `decision_instances` from a hardware probe plus the catalog plan; it is not purely static: its RAM budget is the smaller of live `MemAvailable` minus 4 GiB and 60% of `MemTotal` minus the reservations of running llmctl profiles, and its VRAM budget uses live free VRAM where that is measurable; but it reads no PSI, no CPU load, no cgroup limit and gives no per-profile verdict, so it MUST NOT by itself produce `fits` under this anchor. Until a source that satisfies the contract is vendored, the verdict is `undetermined` unless the consumer computes the contract from the same kernel interfaces itself, as a documented and tested script (§11.4.274), never as an inline guess.

**(D) DYNAMIC RE-EVALUATION, INCLUDING A RUNNING MODEL.** The verdict is re-evaluated at every start request, at every bootstrap and status run (§11.4.281), on demand, and on a cadence while a local decision model this host's constitution sessions route to is running (cadence consumer DATA). (1) DEGRADATION: when the verdict for a running instance becomes `does_not_fit` (the agent sessions grew, pressure crossed a threshold, the unit reports `degraded`), the session moves its decision traffic to the fallback of clause (E) FIRST; requests already in flight to the local endpoint then drain for at most a consumer-declared drain timeout; then the session releases its lease (clause (J)), and the model is stopped with `llmctl stop` (a graceful stop through llmctl; never a raw signal to a process group, §11.4.263) only by the holder of the last lease and only when the model is constitution-started. A request still in flight when the drain timeout ends is re-issued on the new route or, where it cannot be re-issued, escalated per §11.4.284(C), and is recorded as re-issued; no decision is silently lost, and this anchor does not claim that no request is ever interrupted. The transition is recorded and announced per clause (F). (2) RECOVERY: traffic returns to the local model only after the verdict has read `fits` (or `fits_with_reduced_threads`) for a consumer-declared hold window, so the route does not flap; the window is DATA, never a constitutional literal. (3) OWNERSHIP: the constitution stops only models constitution automation started, as recorded in the lease set of clause (J); a model the operator started or enabled is never stopped by the constitution: the constitution routes traffic away from it, records the verdict and tells the operator. (4) A re-evaluation never blocks the work it protects: it runs with a bounded time budget and an exhausted budget yields `undetermined` for that round (§11.4.232(C)).

**(E) FALLBACK — `cloud` when a key is present, `none` when not.** When no candidate profile reads `fits` or `fits_with_reduced_threads` (and no override of (A.1) applies), the route is the one the capacity source recommends in `fallback.recommended`, checked by the consumer: (1) route `cloud`: a hosted decision endpoint's key is present and not a placeholder, detected BY VARIABLE NAME exactly as §11.4.279(E) prescribes (read in a subshell, the value never printed, logged, stored or put on a command line, §11.4.10); decision traffic goes to that hosted endpoint, and every §11.4.279(E)(3) rule follows it, in particular a hosted endpoint NEVER enforces, so question types that were enforced on a calibrated local endpoint return to SHADOW while traffic is hosted, and that drop is part of the notice; (2) route `none`: no such key is present; the decision layer has no endpoint for that period, which is lawful only with the reasoned record of §11.4.279(B) naming this anchor's verdict as the reason, and typed decisions escalate exactly as §11.4.284(C) describes for a decision below threshold; (3) in neither case is the local model started. When the capacity source is unavailable (`undetermined` for every candidate), the consumer applies the same two cases from its own §11.4.279(E) key detection. The hosted traffic is decision serving, not detection; the §11.4.279(B) rule that detection does no hosted network I/O at work-item time is unchanged.

**(F) THE OPERATOR IS INFORMED — visible and recorded, never silent.** Every placement transition (`local` to `cloud`, `local` to `none`, `cloud` or `none` back to `local`, `fits` to `fits_with_reduced_threads`, an endpoint gone per (J)(6), a start under an override of (A.1)) produces (1) a visible notice on the operator's channel in that run (the bootstrap or status output on stderr, the session report, the §11.4.97 progress report) naming the profile, the verdict, the deciding inputs with their values and the new route; and (2) a `placement` entry in the project's `jev-detection.json` with: profile, verdict, reason, the clause (C) inputs with source and timestamp, the reserve values used, `decided_at`, `route` (`local` | `cloud` | `none`), the hosted key's variable NAME when the route is `cloud` (never its value), the override id when one applies, whether the model is constitution-started and this session's lease, and the previous verdict. A route that changed without a notice and a record is a §11.4 bluff at the operator-transparency layer. A host that never fits a local decision model is told so once per session and recorded every evaluation, never nagged per decision.

**(G) ON-DEMAND LIFECYCLE ONLY — never `enable` (mandate (3)).** Every constitution-owned script, hook, skill, gate and agent instruction (the bootstrap of §11.4.281, the decision-layer skill, the post-update hook and any wrapper) MAY call `llmctl start <profile>` (after a `fits` or `fits_with_reduced_threads` verdict, or under an override of (A.1)) and `llmctl stop <profile>` (for a constitution-started profile whose last lease it releases per clause (J), when idle past a consumer-declared timeout, on degradation per (D), or at session end), and MUST NOT: call `llmctl enable` or `llmctl disable`, or create, enable or disable a systemd unit or any other boot-start entry for a model; call a llmctl command that stops or evicts models it did not start (for example `switch`, which stops every running model, or `auto` where it may evict); or start a model to "warm it up" with no decision traffic waiting for it. Start at boot is an operator act only, taken outside the constitution's automation. Every llmctl call made by constitution automation runs under a bounded timeout; a call that times out is recorded and yields `undetermined`, it is never retried in a tight loop (§11.4.267) and never waited on without bound, so the host and the session never hang on it. A start that llmctl refuses (exit 75, §11.4.277(E)(3)) is a `does_not_fit` for that round and triggers clause (E).

**(H) NO OOM — what this anchor guarantees and what it cannot.** A `fits` verdict requires the model's footprint (measured where available; a declared footprint is named as declared) plus everything resident plus the reserve to fit the smaller of the live host budget and the scope's `memory.max`; the engine unit's own memory caps (§11.4.277(E)(2)) stay, so a misestimate ends the model, not the host. Honest boundary (§11.4.6): the verdict is a measurement at one moment; other processes can grow after it. The kernel caps, the §11.4.277(E) gates and the clause (D) re-evaluation are the mitigation, and together they make an out-of-memory stall of the host caused by a constitution-started decision model a defect to investigate (§11.4.102), not an accepted risk; this anchor does not claim that no OOM can ever occur on the host.

**(I) HOW THIS REFINES §11.4.279, §11.4.282 AND §11.4.284 (exact).** §11.4.279: the detection record gains the clause (F) `placement` entries; a reasoned-empty record may cite a `does_not_fit` or `undetermined` verdict as its reason. §11.4.282: "use all available model instances to the maximum" counts only instances whose live verdict is `fits` or `fits_with_reduced_threads`; the planned `decision_instances` figure is an upper bound, not a licence to start them, and host-safety headroom stays the only limiter, now measured live. §11.4.284: the pre-ladder stage is unchanged; when this anchor leaves it no endpoint, typed decisions escalate per §11.4.284(C). Each of the three anchors carries a dated refinement note pointing here.

**(J) SHARED INSTANCES — one lease set per profile per host, stop only on the last lease.** Several constitution sessions, tracks and projects on one host may route to the same llmctl profile at once; ownership follows the §11.4.119 single-owner, §11.4.176 exactly-once claim and §11.4.272(D) reference-count pattern. (1) Every constitution session that routes decision traffic to a local profile holds a lease on it in a per-user, host-level lease registry (location consumer DATA, outside any one project tree), naming the session id, the project, the holder pid, the time and whether this session's start request started the model; leases are acquired and released under a lock with a bounded wait. (2) The model is constitution-started when the session holding the first lease started it; that fact belongs to the lease set, not to one session, and survives that session ending. (3) `llmctl stop` is called only by the session releasing the LAST lease, only when the model is constitution-started, and only after its own drain (D)(1); every other session that ends or degrades releases its lease and moves its own route. (4) A lease whose holder is dead (the pid fails `kill -0`, or `/proc/<pid>/cmdline` no longer names the holder, §11.4.180, §11.4.196(D)) is reaped; a live holder's lease is never taken. (5) An operator-started or operator-enabled model may carry leases (routing), but is never stopped by the constitution, whatever the lease count. (6) ENDPOINT GONE: when the local endpoint stops answering or its unit is no longer running (stopped by the operator or another party, killed by the kernel, crashed), every session routed to it moves to the clause (E) fallback at once, records the transition with reason `endpoint_gone`, gives the clause (F) notice and releases its lease; it does not restart the model in a loop, and a restart needs a fresh fitting verdict and the (D)(2) hold window.

**Honest boundary (§11.4.6).** This anchor mandates the mechanism and claims no measurement of placement: no placement verdict has been computed on any host under it, `llmctl capacity --json` is not in the vendored pin (llmctl 3.3.2) at the time of writing (its contract in clause (C) is read from an uncommitted llmctl 3.4.0 working tree and one run of it), the producer of the `placement` record and the lease registry are not written, and none of the gates named below is implemented. It does not change the llmctl engine, its units or its reserve values (that is llmctl's own work under §11.4.277(E)), does not alter the hosted-never-enforces rule, and does not make a hosted endpoint trustworthy beyond what §11.4.279(E) states. Reading `undetermined` as "do not start a local model" until llmctl 3.4.0 is vendored is the conservative reading this text takes (§11.4.201(4)); the operator can lift it per host and profile only through the explicit override of (A.1). Whether the operator wants that interim default is recorded as an open question, not as an operator decision.
