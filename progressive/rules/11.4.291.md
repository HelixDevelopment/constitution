### §11.4.291 — Capacity-aware decision-model placement: a local decision model runs only when the host's LIVE load leaves room for it; otherwise decision traffic falls back, visibly and with a recorded reason, to the hosted endpoint when its key is present (or to a reasoned absence when it is not); the placement is re-evaluated at any time, including while a model runs; the constitution starts and stops llmctl models on demand and never enables them for boot (User mandate, 2026-10-28)

**Forensic anchor — verbatim operator mandate (2026-10-28), mandate (1):** "If host is not powerful enough to work with local decision model in parallel with current work load of the same host, then user has to be informed and use of the locally run decisions model switched to cloud provider such as Jev (if api key is available)! We MUST BE aware that certain hosts can or cannot deal with its current work load (CLI agents we use and sessions we have) + decisions model being executed! This MUST BE smooth and dynamic and the constitution MUST be extended to determine the load, the capacity and if and which exactly decision model can fit and run without issues! We MUST NOT get into any OOM or similar situations!" Two further mandates of the same day, relayed by the conductor and NOT verbatim: (2) llmctl local models must never take all CPUs or all RAM; a reserve always stays free for the system; (3) the constitution uses llmctl only when needed — start and stop on demand, never `enable` triggered by the constitution; `enable` (start at boot) is a separate operator choice only, and the system must never hang.

**The gap this anchor closes (stated so it is not restated elsewhere, §11.4.227).** §11.4.282(A) computes decision capacity from `llmctl plan --json` `decision_instances` and §11.4.277(E)(3) refuses an engine start under memory pressure. Neither decides, BEFORE the decision layer routes traffic, whether a local decision model fits NEXT TO the host's current work (the agent sessions, builds and other services already running), neither tells the operator when it does not, neither defines the switch to the hosted endpoint, and none says who may start, stop or enable a model. A pressure refusal at start time is the last line; this anchor is the line in front of it.

**(A) PLACEMENT VERDICT — closed set, per decision profile.** Before a decision profile is started, before decision traffic is routed to a local instance, and at every re-evaluation of clause (D), the project MUST obtain a placement verdict for each candidate profile from the closed set `{fits, fits_reduced, does_not_fit, undetermined}`: `fits` — the profile at its declared configuration fits next to the live load with the host reserve of clause (B) intact; `fits_reduced` — it fits only in a reduced configuration the profile itself declares (fewer parallel slots, fewer threads, smaller context; the reduced configuration is named in the record and is what is started); `does_not_fit` — it does not fit in any declared configuration; `undetermined` — an input of clause (C) could not be measured, a probe timed out, or the capacity source is absent. `undetermined` is NEVER read as `fits` (§11.4.201(4), §11.4.6): for a start it is treated exactly as `does_not_fit`.

**(B) HOST RESERVE — the model never takes the whole host (mandate (2)).** The verdict is computed against a budget that leaves a reserve the model can never use: (1) RAM: the model's footprint plus everything already resident must fit the live budget with the reserve intact, and a decision model counts against the §12.6 ceiling like every other project procedure; the §11.4.277(E)(3) start gate (footprint plus its reserve against `MemAvailable`, memory PSI thresholds) still applies on top and is never relaxed; (2) CPU: the model's thread count leaves cores to the work already running, and interactive degradation is diagnosed with the §11.4.225 throttle accounting, never with load averages alone; (3) threads and processes: the model's threads fit the §12.12 `RLIMIT_NPROC` headroom; (4) GPU: VRAM is budgeted the same way where the profile uses it. The reserve sizes are host-adaptive and are consumer DATA or llmctl reference values (§11.4.35, §12.11); this anchor sets no new number. Making the engine itself keep that reserve (thread count and memory caps of the unit) is llmctl's job (§11.4.277(E)); this anchor requires that whatever the constitution starts has passed a verdict that accounts for it.

**(C) INPUT CONTRACT — measured, live, with provenance.** The verdict reads, at decision time and for the host and the cgroup scope the model would run in: `MemTotal` and `MemAvailable`; memory PSI `some` and `full` (avg10, and avg60 where available); CPU PSI and the load average against the online CPU count; the scope's `memory.max`, `memory.current`, `cpu.max` and the throttle counters of §11.4.225 where the scope has them; the RAM, VRAM, thread and slot footprint of every llmctl profile already running (measured where a run measured it, else declared, the provenance named per value); the candidate profile's footprint with the same provenance; the `RLIMIT_NPROC` headroom; and the reserve values used. Every input carries its source and its timestamp; a value that could not be read is recorded as unreadable, never defaulted (§11.4.6). The canonical source is a llmctl capacity command returning this contract as JSON (`llmctl capacity --json`, being added in llmctl 3.4.0 by separate work; UNCONFIRMED until the vendored llmctl pin ships it and a run of it is captured). Measured fact about the current pin (llmctl 3.3.2, commit `11a9154`): `llmctl decide capacity --json` returns `tier`, `budgets` and `decision_instances` from a hardware probe plus the catalog plan; whether its budgets subtract the live load of other workloads is UNCONFIRMED, it reports no PSI, cgroup or per-profile verdict, so it MUST NOT by itself produce `fits` under this anchor. Until a source that satisfies the contract exists, the verdict is `undetermined` unless the consumer computes the contract from the same kernel interfaces itself, as a documented and tested script (§11.4.274), never as an inline guess.

**(D) DYNAMIC RE-EVALUATION, INCLUDING A RUNNING MODEL.** The verdict is re-evaluated at every start request, at every bootstrap and status run (§11.4.281), on demand, and on a cadence while a local decision model started by the constitution is running (cadence consumer DATA). (1) DEGRADATION: when the verdict for a running profile becomes `does_not_fit` (the agent sessions grew, pressure crossed a threshold), decision traffic is routed to the fallback of clause (E) FIRST and the model is then stopped with `llmctl stop` (a graceful stop through llmctl; never a raw signal to a process group, §11.4.263), so no decision is dropped between the two steps; the transition is recorded and announced per clause (F). (2) RECOVERY: traffic returns to the local model only after the verdict has read `fits` (or `fits_reduced`) for a consumer-declared hold window, so the route does not flap; the window is DATA, never a constitutional literal. (3) OWNERSHIP: the constitution stops only models it started itself (the start is recorded in the placement record); a model the operator started or enabled is never stopped by the constitution: the constitution routes traffic away from it, records the verdict and tells the operator. (4) A re-evaluation never blocks the work it protects: it runs with a bounded time budget and an exhausted budget yields `undetermined` for that round (§11.4.232(C)).

**(E) FALLBACK — hosted when a key is present, reasoned absence when not.** When no candidate profile reads `fits` or `fits_reduced`: (1) if a hosted decision endpoint's key is present and not a placeholder, detected BY VARIABLE NAME exactly as §11.4.279(E) prescribes (read in a subshell, the value never printed, logged, stored or put on a command line, §11.4.10), decision traffic is routed to that hosted endpoint; every §11.4.279(E)(3) rule follows it, in particular a hosted endpoint NEVER enforces, so question types that were enforced on a calibrated local endpoint return to SHADOW while traffic is hosted, and that drop is part of the notice; (2) if no such key is present, the decision layer has no endpoint for that period, which is lawful only with the reasoned record of §11.4.279(B) naming this anchor's verdict as the reason, and typed decisions escalate exactly as §11.4.284(C) describes for a decision below threshold; (3) in neither case is the local model started. The hosted traffic is decision serving, not detection; the §11.4.279(B) rule that detection does no hosted network I/O at work-item time is unchanged.

**(F) THE OPERATOR IS INFORMED — visible and recorded, never silent.** Every placement transition (local to hosted, local to none, hosted or none back to local, `fits` to `fits_reduced`) produces (1) a visible notice on the operator's channel in that run (the bootstrap or status output on stderr, the session report, the §11.4.97 progress report) naming the profile, the verdict, the deciding inputs with their values and the new route; and (2) a `placement` entry in the project's `jev-detection.json` with: profile, verdict, reason, the clause (C) inputs with source and timestamp, the reserve values used, `decided_at`, `route` (`local` | `hosted` | `none`), the hosted key's variable NAME when the route is hosted (never its value), whether the constitution started the model, and the previous verdict. A route that changed without a notice and a record is a §11.4 bluff at the operator-transparency layer. A host that never fits a local decision model is told so once per session and recorded every evaluation, never nagged per decision.

**(G) ON-DEMAND LIFECYCLE ONLY — never `enable` (mandate (3)).** Every constitution-owned script, hook, skill, gate and agent instruction (the bootstrap of §11.4.281, the decision-layer skill, the post-update hook and any wrapper) MAY call `llmctl start <profile>` (after a `fits` or `fits_reduced` verdict) and `llmctl stop <profile>` (for a profile it started, when idle past a consumer-declared timeout, on degradation per (D), or at session end), and MUST NOT: call `llmctl enable` or `llmctl disable`, or create, enable or disable a systemd unit or any other boot-start entry for a model; call a llmctl command that stops or evicts models it did not start (for example `switch`, which stops every running model, or `auto` where it may evict); or start a model to "warm it up" with no decision traffic waiting for it. Start at boot is an operator act only, taken outside the constitution's automation. Every llmctl call made by constitution automation runs under a bounded timeout; a call that times out is recorded and yields `undetermined`, it is never retried in a tight loop (§11.4.267) and never waited on without bound, so the host and the session never hang on it. A start that llmctl refuses (exit 75, §11.4.277(E)(3)) is a `does_not_fit` for that round and triggers clause (E).

**(H) NO OOM — what this anchor guarantees and what it cannot.** A `fits` verdict requires the model's footprint (measured where available; a declared footprint is named as declared) plus everything resident plus the reserve to fit the smaller of the live host budget and the scope's `memory.max`; the engine unit's own memory caps (§11.4.277(E)(2)) stay, so a misestimate ends the model, not the host. Honest boundary (§11.4.6): the verdict is a measurement at one moment; other processes can grow after it. The kernel caps, the §11.4.277(E) gates and the clause (D) re-evaluation are the mitigation, and together they make an out-of-memory stall of the host caused by a constitution-started decision model a defect to investigate (§11.4.102), not an accepted risk; this anchor does not claim that no OOM can ever occur on the host.

**(I) HOW THIS REFINES §11.4.279, §11.4.282 AND §11.4.284 (exact).** §11.4.279: the detection record gains the clause (F) `placement` entries; a reasoned-empty record may cite a `does_not_fit` or `undetermined` verdict as its reason. §11.4.282: "use all available model instances to the maximum" counts only instances whose live verdict is `fits` or `fits_reduced`; the planned `decision_instances` figure is an upper bound, not a licence to start them, and host-safety headroom stays the only limiter, now measured live. §11.4.284: the pre-ladder stage is unchanged; when this anchor leaves it no endpoint, typed decisions escalate per §11.4.284(C). Each of the three anchors carries a dated refinement note pointing here.

**Honest boundary (§11.4.6).** This anchor mandates the mechanism and claims no measurement: no placement verdict has been computed on any host under it, `llmctl capacity --json` does not exist in the vendored pin (llmctl 3.3.2) at the time of writing, the producer of the `placement` record is not written, and none of the gates named below is implemented. It does not change the llmctl engine, its units or its reserve values (that is llmctl's own work under §11.4.277(E)), does not alter the hosted-never-enforces rule, and does not make a hosted endpoint trustworthy beyond what §11.4.279(E) states. Whether the operator wants `undetermined` (no live capacity source yet) to keep a local model from starting on every host until llmctl 3.4.0 is vendored is the conservative reading this text takes (§11.4.201(4)); it is recorded as an open question for the operator, not as an operator decision.
