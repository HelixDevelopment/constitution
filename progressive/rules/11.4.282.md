### §11.4.282 — Maximal decision-instance utilization (User mandate, 2026-10-07)

**Forensic anchor — verbatim user mandate (2026-10-07; the shared mandate is quoted in full in §11.4.279):** "Use all available model instances to the maximum."

**(A) CAPACITY IS COMPUTED, NOT GUESSED.** Every incorporating project MUST compute its decision capacity from `llmctl plan --json` `decision_instances` (per-profile instance counts under the host's RAM/VRAM headroom rules) and record it in `jev-detection.json`.

**(B) DECISION WORK USES DECISION CAPACITY.** Whenever more than one decision endpoint or instance is available, decision traffic (gates, routing, scoring, calibration probes) MUST be distributed across them — local instances first, then LAN pins, then hosted — with per-endpoint concurrency bounded by the profile's `parallel` slots. A single pinned endpoint used while idle local capacity exists is non-compliant.

**(C) DEGRADATION IS EXPLICIT.** If instance count is 1 or 0, that is recorded with the reason (tier gate, budget refusal, download absent); the ladder of §11.4.231 proceeds unchanged.

**(D) GATE.** Covered by `CM-JEV-DETECTION` (capacity fields present) and a §11.4.283 harness assertion (traffic distribution evidence in `decisions.jsonl` endpoint field). No separate gate-code.

Composes with §11.4.279 / §11.4.141 / §11.4.231 / §9 (host-safety budget rules are never overridden for utilization).

Classification: universal (§11.4.17). Propagation gate `CM-COVENANT-114-282-PROPAGATION`.

**Canonical authority:** constitution submodule [`Constitution.md`](Constitution.md) §11.4.282.

**Non-compliance is a release blocker. No escape hatch — host-safety headroom (§12) is the ONLY legitimate capacity limiter.**

**Refinement note (2026-10-28).** §11.4.291 bounds "to the maximum": only instances whose LIVE placement verdict is `fits` or `fits_with_reduced_threads` count, the planned `decision_instances` figure is an upper bound and never a licence to start them, and host-safety headroom (the only limiter, per the close above) is measured live per §11.4.291(C).

**Refinement note (2026-11-12).** "All instances are used actively": decision traffic goes first to the live-fitting local instances (placed by `scripts/jev/jev-place.sh`, which registers the local gateway in the decision-endpoint cache at priority 10, ahead of the hosted entries), then spills over to the hosted endpoints in cache order; an endpoint that answers non-2xx is skipped for the next one. The spill-over order is executed by the claude_toolkit gate and MCP server, which this repository does not ship; the constitution side writes the cache entry and the placement record and does not claim the toolkit's failover behaviour. Thresholds are calibrated per (endpoint, model) as well as per question type (`per_endpoint` in `jev-thresholds.json`); a group enforces only when it meets the §11.4.285 floors on its own.

**Refinement note (2026-11-13, factual, round-6 review R5-10; flagged for independent review).** "Decision traffic goes first to the live-fitting local instances" is qualified as follows. The `llmctl-local` cache entry is derived from the lease registry at every registry write and names only a set that holds a lease, carries no `starting` or `stopping` mark and no failed start or owed stop, and whose own unit an observation newer than its start read as `ok`. A held set whose unit turns `degraded` leaves the cache at the next observation (any `heartbeat`, `status`, `verdict`, `reap`, `acquire` or `release`), not continuously: no re-evaluation cadence runs today and no session calls the producer, so in normal use no local instance is placed. Gate-logic evidence only (§11.4.289(C)(2)). Added 2026-11-13 (round 7, review nit N6-c): the entry also requires a recorded `https://` gateway object in the lease registry; without one no `llmctl-local` entry is written (the scheme is matched case-sensitively, so `HTTPS://` is refused, fail-closed; a separate item by operator decision).
