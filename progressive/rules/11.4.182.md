**§11.4.182 — Track+branch work-stream identity label `(T<N>/<branch>)` on every agent/subagent/work-stream label and every operator-facing work-stream reference (User mandate, 2026-07-05).** **Forensic anchor — operator mandate (2026-07-05):** "EVERY agent/subagent/work-stream label AND every operator-facing report reference to a work stream MUST carry a `(T<N>/<branch>)` prefix identifying the track + git branch — e.g. `(T1/main) ATM-312 MPV drm_prime investigation`, `(T2/feat/mistiq-vader) SPK-XXX ...`." In a multi-track layout (parallel checkouts each on a distinct branch — e.g. `/mnt/track1..4`) a bare work-stream label ("ATM-312 investigation") does not say WHICH track/branch produced it, so cross-track dispatches, status reports, and progress lines collide and mislead. The mandate (ALL hold): (1) **Universal label form.** Every agent / subagent / work-stream label AND every operator-facing reference to a work stream (agent-dispatch descriptions, status reports, resume/handoff docs, progress lines) MUST START with a `(T<N>/<branch> - <alias>)` prefix — `<N>` the track number, `<branch>` the git branch, `<alias>` the claude-toolkit alias in use — e.g. `(T1/main - claude1) ATM-312 MPV drm_prime investigation`, `(T2/feature/mistiq-vader - deepseek) SPK-XXX subtitle work`. (2) **Deterministic derivation, never guessed (§11.4.6).** The label is DERIVED, not typed from memory: `<N>` from the checkout path (the multi-track root `/mnt/track<N>/…`; honest `?` when the checkout is not under a numbered track — never a guessed number), `<branch>` from `git rev-parse --abbrev-ref HEAD`, `<alias>` from `CLAUDE_CONFIG_DIR` basename `.claude-<alias>` → `<alias>` (honest `?` when unset/non-matching, never a guessed name). The consuming project supplies a deterministic labeler (reference impl `scripts/multitrack/track_branch_label.sh`). (3) **Mechanical enforcement (§11.4.75 / §11.4.109-class anti-forgetting).** A PreToolUse guard hook (reference impl `constitution/scripts/hooks/guard-track-branch-label.sh`, inherited BY REFERENCE per §11.4.177, never copied) BLOCKS at the tool-call boundary any agent-dispatch tool (Agent / Task / TaskCreate) whose `description` (or `subagent` label) does not START with `^\(T[0-9]+/[^)]+\) ` — so enforcement is independent of any agent's recall (a rule the orchestrator forgets to paste is not enforcement); non-agent tools pass through untouched. A pre-build gate `CM-TRACK-BRANCH-LABEL` asserts the labeler + hook exist, are executable + parseable, the hook is wired in the runtime settings, and the convention doc exists; a propagation gate `CM-COVENANT-114-182-PROPAGATION` asserts the literal `11.4.182` is present across the governance-file fleet. Paired §1.1 mutation: strip the hook's prefix-check → the hook test-suite FAILs; strip the `11.4.182` literal from a governance file → the propagation gate FAILs; restore → PASS. (4) **Honest boundary (§11.4.6).** A `?` in the track OR the alias field is a valid honest label (unknown track / no git repo), never a bluff; the enforced FORMAT is numeric-track `[0-9]+` per the reference regex, so an agent dispatch from a non-track checkout is surfaced (blocked) rather than silently mislabeled. Classification: universal (§11.4.17) — a platform-neutral multi-stream identity discipline reusable by any project running parallel track/branch work streams; the consuming project supplies its concrete track-root layout, labeler, hook wiring, and governance-file set per §11.4.35. Propagation gate `CM-COVENANT-114-182-PROPAGATION` (literal `11.4.182` across the consumer fleet) + recommended gate `CM-TRACK-BRANCH-LABEL` + paired §1.1 meta-test mutation. **TRUNK RULE (operator mandate, 2026-07-28):** work performed on the canonical trunk (`main`/`master`) is **ALWAYS Track 1** — the label reads `(T1/main - …)`, NEVER `(T?/main - …)`, regardless of checkout path. Precedence is deliberate: the BRANCH decides first and the checkout path decides only for non-trunk branches, so a trunk checkout living outside `/mnt/track<N>` — or inside a differently-numbered one — is still Track 1; the identity that matters is which STREAM the work belongs to, not which directory it happens to sit in. Rationale: §11.4.182 labels are how concurrent streams are told apart, so an unnumbered `T?` on trunk work makes it indistinguishable from a genuinely-unknown track in every dispatch, report and progress line — and the trunk is a well-known, singular stream that is never unknown. Reference implementation: `scripts/multitrack/track_branch_label.sh` derives the branch BEFORE the track number and maps `main|master -> 1`. Labels MUST be re-derived from that script at dispatch time and kept in real-time sync with the live branch/alias/model/effort — a remembered or stale label is itself a §11.4.182 violation (§11.4.6: live identity is not knowable from memory). **Precedence note (2026-10-26, §11.4.288, relayed operator decisions (1) and (3), not verbatim).** Where this anchor assumes a per-feature or per-track branch as the standing place of work, read it under §11.4.288: work is made on `main` by default; a branch, worktree or clone is a vehicle only when strictly necessary and is landed fast-forward-only and retired before the item counts done; the claim, label, track and device-lock mechanics here apply unchanged to work on `main`. The `<branch>` field of the label is `main` for work on `main`, and the vehicle's name only while a recorded §11.4.288(B) vehicle exists.
