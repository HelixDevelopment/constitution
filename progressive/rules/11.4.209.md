### §11.4.209 — Code-review MUST run on the Opus model at xhigh effort as PRIMARY substrate, with a genuine-unavailability Sonnet fallback — no Fable, no escalation tier (User mandate, 2026-09-26, supersedes 2026-09-15 and 2026-07-15; amended 2026-10-04 to add the Sonnet-fallback clause)

**Verbatim operator mandate (2026-09-26, `CRITICAL`), superseding both mandates below:** "Main model to use is Sonet, reviews and other heavy stuff have to be done by Opus instead of Fable!!! Fix this permanently on all levels!"

**Prior mandate (2026-09-15), WITHDRAWN as current, kept for lineage:** *"the mandatory independent code-review MUST by default be performed with the Opus model at xhigh effort; for a review the operator or the reviewer itself classifies as extremely big or complex, the Fable model at xhigh effort MUST be used instead."* Its Opus-xhigh default survives; its Fable escalation clause (former clause (A)) is REMOVED by the 2026-09-26 mandate — there is no review tier above Opus-xhigh.

**Prior mandate (2026-07-15), WITHDRAWN as current, kept for lineage:** *"the mandatory independent code-review MUST ALWAYS be performed with the Fable model at xhigh effort; if Fable is unavailable, use Opus at xhigh effort."* Inverted by the 2026-09-15 mandate and fully superseded by the 2026-09-26 mandate.

Every mandatory independent code-review the constitution requires — the §11.4.125 code-review-agent gate before pre-build + main build, the §11.4.142 universal every-change-review (no exception), and the §11.4.194 exhaustive all-scenario/all-angle review + verify-against-captured-runtime-evidence, iterated to a zero-finding GO per §11.4.134 — MUST be dispatched on the **Opus model at `xhigh` effort** as PRIMARY substrate, whatever the size or complexity of the reviewed change. **(A) PRIMARY substrate Opus-xhigh + genuine-unavailability SONNET FALLBACK (amended 2026-10-04) — no escalation tier, no Fable, no other fallback model.** Opus at `xhigh` is the PRIMARY and preferred review substrate. Fable is NOT permitted in any role (default, escalation, or fallback), ever; no model other than Opus or the sanctioned Sonnet fallback below, and no lower tier for Opus itself, substitutes for it. When Opus at `xhigh` is genuinely unavailable (not configured / rate-limited / unreachable, established as a captured FACT per §11.4.6 — never a guessed unavailability), the review MUST be dispatched on **Sonnet** (at the highest effort the dispatch path can set) rather than blocked — the sole sanctioned fallback, per the verbatim 2026-10-04 operator mandate above: reviews MUST be done with whatever capable means are actually available, Opus ideally, Sonnet when Opus genuinely cannot be used. The Opus-unavailability FACT and the Sonnet-fallback substitution MUST both be recorded honestly in the review's captured evidence (§11.4.5/§11.4.69) — a Sonnet-fallback review is NEVER silently presented as if it ran on Opus. A review is NEVER left undone / blocked / deferred solely because Opus is unavailable while Sonnet is reachable — maximal efficiency (§11.4.183) forbids leaving genuinely performable review work undone. ONLY when BOTH Opus and Sonnet are genuinely unavailable (each established as its own captured FACT per §11.4.6, never guessed) does the review become BLOCKED and deferred under the original (A) terms: the unavailability fact is recorded, the owed review is tracked (§11.4.197; §11.4.21 once the self-resolution audit is exhausted), and the reviewed change does NOT pass the review gate unreviewed. **(B) Independence preserved (§11.4.70/§11.4.20).** The reviewing model (Opus or the sanctioned Sonnet fallback) runs as the structurally-separated reviewer (never the author self-reviewing); §11.4.209 sets the MODEL + EFFORT of that review, it does not weaken the independence, the iterate-until-GO loop (§11.4.134), or the rock-solid captured-evidence requirement (§11.4.5/§11.4.69/§11.4.107). **(C) Honest boundary (§11.4.6).** A review claimed "done" that actually ran on Fable, Haiku, or any model other than Opus or the sanctioned Sonnet fallback, or at an effort below `xhigh`, or on Sonnet with no recorded Opus-unavailability fact, is a §11.4 bluff at the review-substrate layer — the review's captured evidence MUST record which model + effort actually performed it. Where the dispatch path cannot set or report the effort (the §11.4.231(F.2) harness gap), the evidence records that gap honestly and the review is never claimed to have run at `xhigh` on an unverified basis. **(D) Values already burned in a public repository (§11.4.10).** Any plaintext credential value that has appeared in documentation, a spec, or commit history — including as a worked example — MUST be treated as compromised from the moment of commit; a document illustrating this anchor or any credential-adjacent mandate MUST NOT embed a real-looking username/password pair, even as an example, without the accompanying statement that the pair is compromised-by-disclosure and MUST NOT be relied on as a real secret.
