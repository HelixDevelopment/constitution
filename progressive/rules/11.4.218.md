### §11.4.218 — Living design-library catalogue: every component × state × theme rendered self-contained + a cross-platform reusability matrix with per-cell provenance (User mandate, 2026-07-22)

**Forensic anchor — proving project (Helix Thready MVP design package, 2026-07-22).** Helix Thready's `design/library/` renders the ENTIRE component set as a living catalogue: `components.html` — 14 groups, ~38 components, ≈ 118 component-state cells, each auditable in BOTH themes via a real toggle (≈ 236 rendered states), zero external requests, interactive behaviors REAL not mocked (theme cycling stamps `data-theme` and persists; column sorting drives `aria-sort`; a real `showModal()` dialog; an auto-dismissing toast that pauses on hover) — plus `components-sheet.svg` (an importable one-sheet) and `platform-map.md`, a 36-components × 8-platforms reusability matrix where EVERY cell carries a VERIFIED / PROPOSED / ASSUMED provenance marker re-checked at source.

**The mandate.** Every project governed by this Constitution that ships user-facing interfaces MUST maintain a LIVING design-library catalogue: (1) **Complete component × state × theme rendering** — every component of the project's design system, in every declared state (default / hover / focus-visible / disabled / loading / error / empty / skeleton as applicable), auditable in BOTH light and dark from one artifact; a component or state that exists in the spec but not in the catalogue is a coverage gap, tracked per §11.4.223. (2) **Self-contained artifacts** — the catalogue renders with ZERO external requests: no CDNs, no external fonts (self-hosted or system-stack fallback stated honestly), vendored libraries inlined; a catalogue that needs the network is not auditable offline and violates the project's CSP/offline posture. (3) **Real behaviors, token-bound** — interactive exhibits are real (real dialog, real sort, real toggle), every color/size binds to the §11.4.216 token source, and all motion honors `prefers-reduced-motion` per §11.4.221. (4) **Cross-platform reusability matrix with per-cell provenance** — a components × platforms matrix where EVERY cell is marked from the closed provenance set: VERIFIED (reproduced from source and re-checked at source, with the check date), PROPOSED (a `[DEFAULT — adjustable]` design pending review), or ASSUMED (inference, labeled as such); an unmarked cell reads as ASSUMED. The matrix is read BEFORE implementing any component on any platform; scaffolds are named scaffolds — a scaffold cell claiming VERIFIED is a §11.4 PASS-bluff at the design-planning layer.

**Honest boundary (§11.4.6).** The catalogue proves the DESIGN renders and behaves as specified in a browser-class runtime; it does not prove any platform IMPLEMENTATION (that is the matrix's per-cell provenance + each platform's own §11.4.170 rendered-pixel proof), and PROPOSED components are named proposals pending the upstream-vs-project split decision — never silently promoted to shipped.

Classification: universal (§11.4.17) — the consuming project supplies its component set, state vocabulary, platform list, and matrix location per §11.4.35. Composes §11.4.6 / §11.4.162 / §11.4.170 / §11.4.216 / §11.4.221 / §11.4.223. Propagation gate `CM-COVENANT-114-218-PROPAGATION` (literal `11.4.218`) + recommended gate `CM-DESIGN-LIBRARY-LIVING-CATALOGUE` (the catalogue artifact exists, is self-contained — zero external URL references —, covers every spec'd component × state in both themes or tracks the gap, and the reusability matrix carries a closed-set provenance marker in every cell) + paired §1.1 mutation (introduce a CDN reference → gate FAILs; blank a matrix cell's marker or claim VERIFIED on a scaffold row → gate FAILs; strip the literal → propagation gate FAILs; gate-code = separate work item).

**Canonical authority:** constitution submodule [`Constitution.md`](Constitution.md) §11.4.218.

Non-compliance is a release blocker regardless of context. No escape hatch — no `--cdn-in-catalogue`, `--single-theme-catalogue`, `--mocked-behaviors-OK`, `--unmarked-matrix-cell`, `--scaffold-claims-verified` flag exists.
