### §11.4.279 — Decision-model detection-first mandate (User mandate, 2026-10-07)

**Forensic anchor — verbatim user mandate (2026-10-07), quoted in full as the shared forensic source for §11.4.279–§11.4.286:** "Any project that uses the constitution must: first detect any decision models available (llmctl local instances and providers); install all plugins, skills, and MCPs per agent; auto-tune immediately when the constitution updates; provide interactive-but-automated wizards; use all available model instances to the maximum; reduce token consumption of traditional LLMs to the maximum; trigger out-of-the-box entry points when a new constitution version lands; and make llmctl and claude_toolkit part of the constitution submodule with mechanisms for installing. Traditional LLMs must auto-tune the Jev models." This anchor's operative slice: "Any project that uses the constitution must first detect any decision models available — llmctl local instances and providers — before any other LLM work proceeds."

**(A) DETECTION BEFORE GENERATION.** Every project incorporating this constitution MUST run decision-model detection — `llmctl plan --json` (local `decision_instances`) and `claude-providers sync-jev` (ranked endpoint cache: local decide gateway, LAN pins, OpenRouter, TypeSafe hosted, in that priority order) — before the first generative-LLM invocation of any work item. Detection output MUST be persisted to the project's evidence store as `jev-detection.json` (endpoint list, per-endpoint model IDs, probe timestamps, absence reasons).

**(B) DETECTION IS CHEAP AND ALWAYS-ON.** Detection MUST NOT perform network I/O against hosted providers at work-item time; it reads the toolkit's TTL-guarded cache and llmctl's local plan. Hosted endpoints enter the cache only at explicit sync time. Detection absent any endpoint MUST produce an explicit `{"endpoints": [], "reason": "…"}` record — silent absence is a §7.1 bluff.

**(C) NO DETECTION, NO GENERATION CLAIM.** Any session report, cost report, or token-efficiency claim (§11.4.141) that does not reference the session's `jev-detection.json` is non-compliant. A project with zero detected decision endpoints is compliant only when the detection record proves the absence.

**(D) GATE.** Gate `CM-JEV-DETECTION` asserts: the detection command ran within the work item's evidence window; the output parses; absence is reasoned. Paired §1.1 mutation: `cm_jev_detection_mutation_test.sh` fabricates a detection record while `llmctl` and all endpoints are absent in the sandbox — the gate MUST fail.

**(E) OPERATOR KEY-FILE AUTO-DISCOVERY — IMMEDIATE USE OUT OF THE BOX (operator mandate 2026-10-24, verbatim: "If Jev (Typesafe AI) API key is present in api_keys.sh, Jev decisions model MUST BE used out of the box immediately and all decision models related rules / technology used and applied!").** (1) Every governed project, with no per-project opt-in, MUST auto-discover decision-model credentials from the operator's key file (default `~/api_keys.sh`, overridable by `JEV_API_KEYS_FILE`) by variable NAME, read inside a subshell, the value never printed, logged, persisted or put on a command line (§11.4.10); the names are those declared by the claude_toolkit provider pins (`scripts/providers/jev.json`: hosted `typesafe` = `TYPESAFE_API_KEY`, `openrouter` = `OPENROUTER_API_KEY`, `local_gateway` = `LLMCTL_API_KEY`), read from the pin and never guessed. (2) A present, non-placeholder key (placeholder: shorter than 16 characters or a known dummy, treated as absent with the reason recorded and never the value) for the Jev/TypeSafe AI hosted endpoint, or the local gateway key, MUST cause the decision layer to be detected, probed, installed under the §11.4.280 consent rules and served in SHADOW MODE by that same bootstrap run once the consent rules allow it (provisioning and per-agent wiring need the §11.4.280 opt-in; without it the run records `wiring-pending` and edits no agent configuration); the post-update hook runs the bootstrap only when a pull changes a Jev-layer file, so a key added later is picked up by the next bootstrap run, not instantly; no separate enablement flag exists. (3) From that moment every decision-model rule applies: the detection-first record (A), per-agent wiring with stated coverage gaps (§11.4.280), the §11.4.231(G)/(C) exclusions (no review, merge, finding-layer, QA, readiness, evidence or verifier decision is ever served), the §11.4.277 validation gate before any gating use, the measured token-reduction proof, calibration before enforcement and the idempotent bootstrap (§11.4.281); a hosted endpoint NEVER enforces, so "used immediately" means served in shadow, and enforcement needs calibration plus a fresh validation. (4) An absent, placeholder or unreadable key file is a lawful reasoned-empty detection record, never a silent skip and never a failure of the host project. (5) A key file readable by group or others MUST be reported as a warning (§11.4.10). (6) Honest boundary (§11.4.6): this clause mandates the mechanism and claims NO live measurement. The live figures that an earlier draft of this clause quoted (decision counts, per-profile pass counts, latency, tokens per decision) cite no durable evidence path, record id or command in this tree and are therefore UNCONFIRMED and withdrawn (§11.4.262, §11.4.5); a re-measurement must be committed with its raw files and producing commands before any figure is restated. The only first-hand observation available at the time of this fix is scratch evidence outside this repository (2026-10-26, one host, not committed, so it is not citable): one authenticated request to the hosted decision endpoint returned HTTP 2xx, and the local profile `decide-laya` held a fresh validation record; both stay UNCONFIRMED as claims. The bootstrap with the real key file, no provisioning and no agent wiring recorded the hosted endpoint and its variable name, and the key itself was never printed; whether the hosted endpoint verifies the key (as opposed to answering 2xx regardless) is UNKNOWN. NOT claimed: correctness beyond fixtures, a measured token-reduction proof from a real hosted run, behaviour under provider timeouts (UNCONFIRMED), enforcement (a hosted endpoint never enforces) and validation of any profile. Covered by the detection gate (`CM-JEV-DETECTION`); no new gate name is minted.
